1Introduction

What X-Ray Calc 3 does, the calculation method, and the reference publication

X-Ray Calc 3 (XRC3) is an open-source software package for simulating X-ray reflectivity (XRR) and solving the inverse problem of reconstructing film structures from measured XRR curves. It is designed for researchers working with X-ray optics, synchrotron radiation, and thin-film coatings.

The software employs Parratt’s exact recursive method based on the Fresnel equations to calculate XRR and incorporates specialized tools for modeling periodic multilayer structures (PMMs). Refractive indices of materials are computed using the Henke tables of atomic scattering factors (Henke et al., 1993). The computational algorithm has been validated against the IMD software (Windt, 1998), with accumulated variances consistently below 0.5%.

The application allows you to:

  • Build multilayer structural models composed of stacks and individual layers
  • Calculate theoretical X-ray reflectivity curves as a function of incidence angle (θ) or wavelength (λ)
  • Load experimental reflectivity data and compare it with theoretical predictions
  • Automatically fit model parameters to experimental data using the Shake LFPSO (Lévy Flight Particle Swarm Optimization) algorithm
  • Visualize results through interactive charts with logarithmic/linear scaling
  • Define parameter profiles (polynomial or tabulated) across periodic structures
  • Manage materials via the built-in Henke atomic form factor database
Reference: Penkov, O. V., Li, M., Mikki, S., Devizenko, A. & Kopylets, I. (2024). X-Ray Calc 3: improved software for simulation and inverse problem solving for X-ray reflectivity. J. Appl. Cryst. 57, 555–566. https://doi.org/10.1107/S1600576724001031

This section provides a hands-on introduction to X-Ray Calc 3. The distribution includes several demonstration projects in the Examples folder — open one to explore the interface before building your own models.

Exploring the Demo Projects

  1. Click Open and navigate to the Examples folder.
  2. Select a project file (.xrcx).
  3. Click Calculate on the chart toolbar (or press F5). Calc > Calc all models (F6) calculates all models at once.

Navigating the Interface

  • Double-click a model name in the Project Items list to open its Properties dialog (name, color, description). The same dialog is available from the right-click context menu.
  • Double-click a layer to open the Layer properties dialog, where you can change material, thickness, roughness, and density.
  • Double-click a stack header to open the Stack properties dialog, where you can rename the stack and change the number of periods.
  • Use the Stack and Layer toolbar panels to add, insert, or delete structural elements.

Creating a Model from Scratch

  1. Create a new project (File > New project).
  2. Select Model 1 in the project tree.
  3. Add a stack: Structure > Add Stack (or use the toolbar). In the dialog, set the stack name (e.g., “Main”) and the number of periods (default: 1 for non-periodic structures).
  4. Select the stack by clicking its title in the structure panel.
  5. Add layers: click Add Layer (or Structure > Add Layer). Fill in the material (click “...” to select from the Materials Database), thickness, roughness, and density. Repeat for each layer.
  6. Calculate the reflectivity: press F5 (or Calc > Calculate).

Calculation Settings

  • Mode: Reflectivity can be calculated as a function of grazing angle or wavelength.
  • Polarization: sp is the unpolarized average (Rs + Rp)/2 and takes about twice as long as s. At small grazing angles the two differ little (sp is lower than s by about 1.5 % at 5° and 6 % at 10°), so s is the usual choice for hard X-ray XRR; use sp for an unpolarized source at larger grazing angles.
  • Number of points (N): Controls calculation precision. Calculation time scales linearly with N.
  • Angle range: Set with θ1 and θ2. Check 2θ for θ-2θ geometry. dθ is the angular resolution: the FWHM (degrees, in θ) of the Gaussian the calculated curve is convolved with (0 = none).
  • Scale: Toggle between Linear and Log scale using the toolbar button. Set a background level if needed.
  • Legend: Click items in the chart legend to toggle curve visibility.

Exporting Results

  • The Export button on the Result panel saves the calculated curve to an ASCII file or copies it to the clipboard.
  • The Save button on the Plot panel saves the chart as a bitmap image.

Project Files

Projects are saved as .xrcx files. Internally, an .xrcx file is a ZIP archive containing:

  • project.dsc — the project tree, including the structure of every model
  • params.dsc — the calculation, fit and chart settings, and the project's state (active model, linked data, curve styles)
  • calc.dat — the calculated curve of the active model
  • data_<ID>.dat — one file for each data curve

Creating a New Project

  1. Choose File > New project (or click the New toolbar button).
  2. The program asks Save the current project before starting a new one? (see below).
  3. A new, untitled project is created: one model holding a bare Si substrate, no data, and empty profile, Convergence and Diagnostics pages.

Opening a Project

  • File > Open project ... — browse for a .xrcx file
  • File > Recent projects — select from up to 10 recently opened projects
  • Open toolbar button — click the dropdown arrow for recent projects

Once the file is chosen, the program asks Save the current project before opening another one? before the current project is replaced. The Reopen toolbar button, which reloads the current project from its file, does not ask.

Save / Don't save / Cancel

The program does not track changes, so New, Open and a recent project always ask (Exit only asks Exit X-Ray Calc 3? and does not offer to save):

  • Save saves the current project (Save project As for an untitled one) and then goes on. Cancelling the Save As dialog cancels the command too.
  • Don't save goes on without saving; unsaved results are lost.
  • Cancel (or Esc) keeps the current project open.

Saving a Project

  • File > Save project — save to the current file
  • File > Save project As ... — save with a new name/location

Auto-Save

The program does not keep a backup of the open project, and nothing is restored at the next launch. With Automatically save results to output folder after fitting on in Settings, a fit saves a copy of the whole project as <project>-fitted.xrcx; see Results & Export > Auto-Save Results.

The temp.lock File

Opening a project does not lock it, and a second instance of the program is not stopped. The lock file temp.lock guards the shared working folder %TEMP%\X-RayCalc3, where every open project is unpacked into a subfolder of its own. The first instance to start creates the lock; at exit that instance deletes it and clears the folder. An instance that starts while the lock exists works normally but leaves the folder alone at exit. If the owning instance did not close normally, the lock stays behind and the folder is no longer cleared; delete temp.lock while no instance is running.

Project Tree Organization

The project tree shows items in a hierarchy:

  • Model Group: Contains all structural models
    • Individual models (each with its own layer structure and calculation parameters)
    • Extensions (profile functions attached to models)
  • Data Group: Contains experimental data sets
  • Folders: User-created organizational folders
Tip: Right-click the project tree for context menu operations.

  2. A new model appears in the project tree with a default empty structure.

Duplicating a Model

Select a model in the project tree and choose Project > Duplicate Model to create an exact copy, including all layers, stacks, and parameters.

The Structure Editor

The structure editor is a visual panel in the middle column that displays the current model’s layer structure. It shows:

  • Stacks — repeating periodic units containing one or more layers
  • Single layers — stacks with N = 1; every layer belongs to a stack
  • Substrate (bottom) — the base material

The medium above the structure is always vacuum (ε = 1); it is not shown and cannot be edited.

Each element in the structure is displayed as a colored block with its parameters.

Terminology

The following terminology is used throughout XRC3 (as defined in Penkov et al., 2024):

  • Material — the chemical composition of a layer (e.g. Mo, SiO2, B4C). Used to look up atomic scattering factors, atomic weights and table densities in the embedded database. Cannot be changed during fitting.
  • Layer — the basic geometrical entity. A layer consists of a material and has three parameters: thickness (H), roughness (σ) and density (ρ). All three are adjustable during fitting.
  • Stack — a set of layers. It can be single (non-repeating) or periodic (repeated N times).
  • Structure — a set of stacks, including a substrate. The substrate is a special stack consisting of a single layer with infinite thickness.

Stacks (Periods)

A stack represents a periodic multilayer structure — a group of layers repeated N times.

Adding a stack

  1. Select the model in the project tree.
  2. Choose Structure > Add Stack or use the structure toolbar.
  3. The Stack properties dialog opens with:
    • Stack name: A label for the stack
    • N: Number of repetitions (periods)

Add Stack appends the new stack at the bottom of the structure, just above the substrate. Insert Stack puts it above the selected stack (at the bottom when no stack is selected), which is the way to add a top layer such as a contamination or oxide film.

Editing a stack

Double-click the stack header in the structure editor to open the Stack properties dialog.

Freezing a stack v3.8.2

Right-click a stack and choose Freeze stack to hold all three parameters (H, σ, ρ) of every layer in it during the next fit, or Thaw stack to release them. The stack header then reads [frozen], or [3/6 frozen] when only part of it is held.

This is the same state the Fitting Limits dialog edits in its Fix columns, offered where you are already looking when you decide a stack is settled. See Staged Fitting.

Layers

Each layer has three primary parameters:

ParameterSymbolUnitDescription
ThicknessHÅ (Angstrom)Physical thickness of the layer
RoughnessσÅ (Angstrom)RMS roughness (Gaussian σ) of the layer’s upper interface; for the top layer it is the surface roughness, for the substrate the roughness of the substrate surface (see Algorithm)
Densityρg/cm³Material density

Additionally, each layer has a material assignment that links it to an entry in the Henke atomic form factor database.

Density 0 and the substrate density v3.9.1

A density of 0 means “use the bulk density from the Henke table”. This holds for every layer and, since version 3.9.1, for the substrate too: a substrate density you enter is now used in the calculation. Earlier versions always used the bulk density for the substrate and silently ignored the value shown.

A density gradient (function profile on ρ) takes the layer’s entered density as its constant term. With ρ = 0 it therefore starts from zero, not from the bulk value, and the layer is empty in the first period: enter an explicit density before adding a density gradient.

So that old results do not change, a project saved by an earlier version opens with its substrate density set to 0 (bulk), which is what those models were always computed with. To use a specific substrate density, for example 2.2 g/cm³ for fused silica or 2.5 for soda-lime glass, enter it and save the project.

Density 0 means the bulk density stored in the Henke table, which is not always the form you have. The table for SiO2 holds crystalline quartz, 2.65 g/cm³. A fused-silica substrate left at 0 therefore puts the critical edge at about 2θ = 0.475° at Cu Kα instead of about 0.433°. Enter 2.2 for fused silica. The Henke table editor shows the bulk density of each material.

Adding a layer

  1. Select a stack or model in the structure editor.
  2. Choose Structure > Add Layer or use the toolbar.
  3. The Layer properties dialog opens with fields for:
    • Layer material: Select or type the name of a material in the materials database (e.g., “Si”, “Mo”, “SiO2”). The name is not parsed as a formula: it must match a Henke table, otherwise the calculation stops with “Material … not found in the database”. Add new compounds with Tools > Create new material ... first.
    • H (Å): Thickness in Angstroms
    • σ (Å): Roughness in Angstroms
    • ρ (g/cm³): Density in g/cm³

Navigating layers

The Layer properties dialog includes << and >> buttons to move to the previous or next layer without closing the dialog.

Layer operations (via Structure menu or toolbar)

  • Insert Layer — insert before the selected position
  • Copy Layer — copy to internal clipboard
  • Paste Layer — paste from internal clipboard
  • Cut Layer — copy and delete
  • Delete Layer — remove the layer

Quick Parameter Editing

In the structure editor, you can adjust layer parameters directly:

  • Click a parameter value to edit it in-place
  • Use the Increment selector (in the structure toolbar) to set the step size for fine-tuning
  • Changes are applied immediately; if Auto-Calc is enabled, the reflectivity recalculates in real time

Undo

Choose Structure > Undo (Ctrl+Z) to revert the last structural modification.

Model Text (JSON)

For advanced users, Structure > Edit as text ... opens a JSON editor showing the raw model definition. This allows direct text editing of the complete structure; Save applies the text, Cancel or the close box discards it.

Each layer carries its material M, the values H (thickness), s (roughness) and r (density), and for each of them the fit limits Hmin/Hmax, Smin/Smax, Rmin/Rmax, the flags HF, SF, RF (fixed) and HP, SP, RP (paired). A limit left out of typed text is set to the value itself, so that parameter has a zero-width fit range until you widen it in the fit limits.

Loading Data from File

  1. Select a model or data item in the project tree.
  2. Choose Data > Load ... or click the Load Data toolbar button.
  3. Pick the file. The dialog opens on XRDML (PANalytical); the other filters are ASCII data (.txt, .csv, .tet), counter files (.dat) and all files. A text file holds two columns (angle or wavelength, and reflectivity; see Data Format); an .xrdml file is read as described below.
  4. The data become a new item under the selected data folder (or the Data root) and appear as a series on the main chart. The header lines at the top of a text file that start with * are copied into the item's description.

Loading XRDML Files

A PANalytical / Malvern .xrdml file (schema 1.0 to 2.x) is read directly, and the file's own facts are used rather than typed in:

  • Angle axis. A 2Theta–Omega scan is in 2θ, a rocking curve in ω. The curve is brought to the unit the 2-theta switch of the calculation settings says, so the chart and the fit see the same angle whichever way the file was scanned.
  • Intensity. Counts are divided by the counting time (beam attenuation factors, when the file has them, are multiplied in) and the curve is normalised to 1 at its maximum. A zero or negative count is replaced by the smallest positive rate before it, but never by more than 1000 counts/s (the value used when none precedes it), as a log chart needs. The peak count rate of the corrected curve (attenuation factors included), the counting time, the detector and the number of floored counts are written into the item's description; the rate the detector itself saw is re-read from the file by Assess XRR quality.
  • Wavelength. The wavelength the file implies is written into the calculation settings: when the file's usedWavelength is intended="K-Alpha", the optic passes both lines and the file gives the Kα2/Kα1 ratio, it is the doublet weighted by that ratio (1.541874 Å for Cu); in every other case (a monochromator or a hybrid mirror, another intended line, no ratio) it is Kα1. A period fitted at Kα1 when the doublet was measured comes out 0.08 % short.
  • Source file. The path of the file is kept in the description as * Source file:, and Assess XRR quality reads the file again for the count rates the chart no longer carries.
Note: the normalisation to 1 at the maximum is a presentation scale, not a measurement: on a well-aligned specimen the maximum is the total-reflection plateau, on one whose plateau is depressed by alignment it is the first Bragg order. The Normalize step still decides the scale a fit works at.

Pasting Data from Clipboard

  1. Copy two-column data from another application (e.g., a spreadsheet).
  2. Choose Data > From clipboard or click the Paste Data toolbar button.
  3. The data become a new item Data N.dat in the Data folder. The same rules as for a text file apply (see Data Format); a spreadsheet copy is TAB-separated and reads directly.

Data Format

A text file holds one point per line, in two columns:

  • Column 1: the angle in degrees, in the unit the 2θ switch of the calculation settings shows (2θ when it is checked, the default; θ when it is not), or the wavelength in Å in wavelength mode. A text file is not converted, and toggling the switch later does not convert data already loaded.
  • Column 2: the reflectivity (or an intensity to be normalised afterwards).

The reader is strict:

  • The two numbers are separated by one TAB (or, in a file without TABs, by one space). A line with a third column, or with several spaces between the numbers, is skipped.
  • Any non-empty line without a TAB switches the reader to space-separated columns for the rest of the file, so a TAB-separated file must not contain a header line without a TAB.
  • The angle must start with a digit; the intensity may also carry a sign. A leading blank or a leading point makes the line skipped. A zero or negative intensity (background-subtracted data) is replaced by the smallest positive value before it, as for an XRDML file. A comma is accepted as the decimal separator.
  • Lines that are not two such numbers are skipped. A zero reflectivity is replaced by the smallest positive value before it (1000 when none precedes it).
  • Lines at the top that start with * are copied into the item's description. A first line containing Sample removes the first 21 lines (the header of the old counter files).

Example (the gaps are single TABs):

* Mo/Si multilayer, 2024-01-15
0.100	1.000000
0.200	0.999850
0.300	0.998200
0.500	0.956300
1.000	0.523100
2.000	0.012450
5.000	0.000023
Tip: You can also copy and paste table data directly from OriginLab Origin. The recommended workflow is to import your raw data into Origin first, then copy-paste the two-column table into X-Ray Calc.

Data Processing

Normalize

Data > Normalize asks for a coefficient and divides every reflectivity value of the active data item by it: 0.099 turns a plateau read at 0.099 into 1.

Data > Normalize (Auto) scales the data so that their maximum lies on the active model's calculated curve: the data are divided by Dmax / Rmodel, where Dmax is the largest measured value below θ = 0.5° (2θ = 1°) and Rmodel the model's value at the first calculated point at or above its angle. The window keeps a first Bragg order that stands above a depressed plateau, on a misaligned specimen, from becoming the anchor; it is the one the MCP server's "scale": "auto" uses. In wavelength mode, or when no point lies below 0.5°, the whole curve is searched. The factor and its angle are added to the data item's description, e.g. * Normalised (Auto): divided by 1.1877 at 2Theta 0.4165. Calculate the model first, over a range that covers the angle of the data maximum; if it does not, the command says so and leaves the data unchanged.

Smooth

Data > Smooth replaces each point by the plain mean of six neighbouring points (three below it, itself and two above), computed on the linear reflectivity. The first three points are left unchanged and the last three take the mean of the last six. On a logarithmic curve this fills Kiessig minima and broadens sharp Bragg peaks, so use it on noisy tails, not on the features the fit reads the structure from. Each click smooths again.

Trim

Data > Trim deletes the data points that lie outside the calculation range (θ1–θ2, or λ1–λ2 in wavelength mode), at both ends. Set the range first. If no point lies inside it, the data are left unchanged.

Note: Normalize, Smooth and Trim change the data item itself and are saved with it at once; Undo covers the structure only. The file you loaded is not touched, so to undo, load it again.

Data Conditioning Walkthrough

Raw experimental data often requires conditioning before fitting. Common issues include a long noisy tail, shadowed regions at low angles, noise, and unnormalized intensity. Here is a typical conditioning workflow:

Step 1 — Normalize. Compare the experimental and calculated intensities at a known point (e.g., the total reflection region). Determine the normalization factor and apply it via Data > Normalize. For example, if the experimental intensity at the plateau maximum is 0.099, divide by 0.099 to bring the curve to unit reflectivity; Data > Normalize (Auto) does the same against the model and records the factor in the item's description. The fit need not take this factor as final: with Solve scale in χ² (on by default) it solves the scale within a window around it, since a single point rarely fixes the absolute level to better than several per cent (see Solving the Measured Scale).

Step 2 — Do not smooth. Leave a noisy tail as it is; the fit weighs it. Data > Smooth is a moving average and also rounds the fringes and peaks. In paired tests of the fitting procedure, fitting a once-smoothed curve was the better choice in only 28–47 % of the fits at plateau counts from 3600 to 605 000; it degraded the period most and pushed the densities of heavy layers up. Use Smooth to look at a curve, not to fit it.

Step 3 — Trim. Remove data points outside the useful range:

  1. Set the calculation angle range to cover only the reliable portion of the data (e.g., 0.4° to 4.5°).
  2. Click Calc and note the χ² value.
  3. Select Data > Trim to discard points outside the calculation range.

Algorithm

XRC3 uses the exact Parratt recursion for specular X-ray reflectivity. The medium above the structure is vacuum (ε = 1) and the substrate is semi-infinite. The dielectric constant of each layer is ε = 1 − 2δ + 2iβ, with δ and β proportional to ρλ²f1/A and ρλ²f2/A (ρ the density, A the molar mass). The atomic scattering factors f1, f2 come from the Henke tables (Henke et al., 1993), linearly interpolated in photon energy, E = 12398.6/λ eV (λ in Å).

Interface roughness is Gaussian. The Fresnel coefficient of every interface is multiplied by a Névot–Croce-type factor exp(−q0q′σ²/2), where q0 = 4π sinθ/λ is the wave-vector transfer in vacuum and q′ the one refracted across the interface; the same factor is applied to s and p. The σ of a layer is the roughness of its upper interface (see Layers).

v3.9.4 The factor uses exactly ½. Up to 3.9.3 it used 0.50299 = (1/1.41)², 0.6 % too large, so a σ fitted now comes out about 0.3 % larger than the same fit gave before (3.00 instead of 2.99 Å). A saved model recalculated with 3.9.4 reflects slightly more at large angles, by roughly (Cu Kα, one rough interface): at and 2θ = 5°, 0.7 % for σ = 3 Å and 2 % for 5 Å; at 2θ = 8°, 1.7 % and 5 %. xrccmd 3.9.3 used half the exponent, its interfaces √2 times smoother than the same σ in the GUI; 3.9.4 matches the GUI.

Reflectivity can be calculated as a function of either the grazing angle or the wavelength. Calculated values below the reflectivity floor (R min in the Chart Info bar, default 10−7) are raised to it; the floor applies to the χ² too.

Calculation Modes

X-Ray Calc 3 supports two calculation modes:

Theta Mode (by angle)

Polarization

  • s-type: S-polarization (TE mode, electric field perpendicular to the plane of incidence)
  • sp-type: unpolarized beam, R = (Rs + Rp)/2, with the same roughness factor applied to both components
Guidance: What decides is the grazing angle, not the photon energy. Away from the critical angle Rp ≈ Rs cos²2θ, so sp is lower than s by the fraction (1 − cos²2θ)/2: under 0.5 % below θ ≈ 3°, about 1.5 % at 5°, 6 % at 10° and 20 % at 20°. Use s-polarization at small grazing angles, where the difference is negligible and the calculation is faster. Use sp-polarization for an unpolarized source at larger angles, for example near-normal EUV and soft X-ray geometries; Rp falls to nearly zero near the Brewster angle, θ ≈ 45°.

Number of Points (N)

The N parameter sets the number of calculated points (default 2000 in a new session; a project that stores none opens with 1000). More points give smoother curves but take longer to compute. In Theta mode N is rounded down to a multiple of the number of threads.

When a measured curve is linked to the model and the model curve is visible, N is not used: the model is calculated at the measured angles.

Running a Calculation

  1. Select a model in the project tree.
  2. Set the calculation parameters (mode, angle/wavelength range, polarization, N).
  3. Choose Calc > Calculate or click the Calc Run toolbar button.
  4. The calculated reflectivity curve appears on the main chart.

When a measured curve is linked, Calculate also reports the χ² against it, and the plain χ², in the Chart Info bar, at the scale shown in the scale pane (see Understanding the Cost Function and Solving the Measured Scale).

Calc > Calc all models (F6, or the Calculate all button on the chart toolbar) calculates reflectivity for every model in the project.

Auto-Calculation

Auto-Calc: When enabled in Settings, the reflectivity is recalculated automatically whenever you modify the structure. This provides real-time feedback as you adjust layer parameters.

Multi-Threading

In Theta mode the calculated points are divided into as many contiguous segments as there are threads, and the segments are computed in parallel (with a linked measured curve, its points are divided the same way). Lambda mode runs on a single thread. Configure the number of threads in File > Settings > Calc & Fit:

  • Auto (Use all) — one thread per logical processor available to the process (default)
  • 2, 4, 8, 12, 16, 32, 64 — limit to a specific number of threads
Performance: With a 16-core CPU, the typical simulation time for XRR ranges from 0.05 to 0.25 s for a periodic multilayer model consisting of 300 stacks of 4 layers each (3000-point curve). This speed enables real-time manual curve fitting.

Fitting adjusts model parameters to minimize the difference between calculated and experimental reflectivity curves. X-Ray Calc 3 uses the Shake LFPSO (Lévy Flight Particle Swarm Optimization) algorithm — a population-based global optimization method with an enhanced “Shake” mechanism to escape local minima (Li et al., 2023; Penkov et al., 2024).

The LFPSO algorithm creates a population of solutions (particles), each being a vector of structural parameters. The population is iteratively modified to produce better-fitting solutions. The Lévy flight is a random walk that uses the Lévy distribution to determine step sizes, providing efficient global exploration due to occasional long jumps. The Shake modification re-initializes the population when convergence stalls, helping the algorithm escape local minima.

Version 3.6 introduces several convergence enhancements that improve exploration/exploitation balance, boundary handling, and shake triggering. Six improvements are always active; the Clerc-Kennedy constriction factor is optional (enabled by default in Advanced Settings).

Prerequisites for Fitting

Before starting a fit, you need:

  1. A defined model with initial parameter estimates
  2. Experimental data loaded into the project, linked to the model and visible on the chart (otherwise the fit stops with Measured curve is not linked!)
  3. Fit limits set for each adjustable parameter

Setting Fit Limits

  1. Select the model in the project tree.
  2. Click the Limits button in the structure toolbar.
  3. The Fitting Limits dialog opens, showing a table of all layer parameters (H, σ, ρ), each with a Fix column and columns for Min and Max.
  4. Click any Min or Max cell to edit its value directly.
  5. Only parameters with Min ≠ Max will be adjusted during fitting. Setting Min = Max pins a parameter permanently; to hold one temporarily, freeze it instead (see below).

Freezing Parameters v3.8.2

Freezing holds a parameter at its current value for the next fit without discarding its limits. This is the difference between freezing and typing Min = Max: a frozen parameter keeps the search window you set, so thawing restores exactly that window, and the value it holds follows the model — it tracks the result of every later fit and every manual edit.

  • Click a cell in a parameter's Fix column to freeze or thaw it. Frozen parameters show X and their limits are greyed.
  • Select one or more rows and use Freeze or Thaw to act on whole layers.
  • Right-click for Freeze this stack, Freeze this layer, Freeze all and Thaw all.
  • Each stack's group header counts what is held — Period stack — all 6 frozen or — 1 of 6 frozen.

A stack can also be frozen without opening this dialog: right-click it in the structure panel and choose Freeze stack or Thaw stack. The stack header then shows [frozen] or [3/6 frozen], and the two views always agree.

Freeze state is saved in the project file, so it survives closing and reopening. Projects written by earlier versions load with nothing frozen.

Frozen parameters are left alone by Initialize, Narrow, Widen and Fix, and are not reported by validation — a frozen parameter with a stale range cannot block a fit.

Physics Constraints

All limit operations automatically enforce physical constraints:

  • H, σ, ρ ≥ 0 (no negative values)
  • ρ ≤ 23 g/cm³ (densest stable element, Osmium)
  • σ Max ≤ min(own H, H of the layer above) — a layer's σ is the roughness of its top interface, so it cannot exceed the layer's own thickness or the thickness of the layer above it (toward the surface; layers are listed surface first). The first layer of a repeating stack takes the last layer of the same stack as the layer above; the first layer of the coating borders the ambient and is bounded by its own H only

The Fitting panel offers three modes: Irregular, Periodic and Polynomial.

Irregular Mode

Every parameter of each layer is treated independently. This mode is used for non-periodic coatings consisting of several layers. At the start of fitting, the software expands each periodic stack into individual layers. Once fitting is complete, distribution charts are generated for each parameter of every material type (thickness, roughness, density).

  • Each layer has its own fitted thickness, roughness, and density.
  • With Smooth checked, each particle's period-to-period profile of every parameter is smoothed with a moving average over the Smoothing window (Advanced Settings) after every update. This is a constraint during the search, not a smoothing of the result; it applies to stacks with N > 1 and to parameters that are neither paired nor frozen (nor given Min = Max).
  • Specific parameters can be “stack-locked” (paired) — e.g. roughness and density remain constant while thickness varies across the stack.
  • The fit writes each period's values into the model's Table extension, which the chart then uses. While the model's Table extension is on — Resume Fitting, Run answered with Keep them, or a reopened project — a fit starts every period from its value in the Table (a frozen parameter is held at each period's own value). A value outside the layer's fit limits starts from the limit, and the program says how many there are before the fit starts: after a Resume the limits are centred on period 1's value, so in a graded stack widen them first. Clear them removes the Table, and every period then starts from the layer's single value, the one the structure panel shows. In 3.9.4.1130 and earlier every Irregular fit started from the single values and the Table was ignored.
Irregular fits made with 3.9.4.1130 or earlier: after the first shake the pairing was lost (every parameter was copied from the first layer), so the search stopped improving at the first shake. Repeat such fits with a later version.
Example: A Mo/Si PMM with 60 repeated stacks would require 726 variables if treated individually. Using the periodic mode, this reduces to just 18 variables.

Periodic Mode

The coating consists of repeated stacks; each stack consists of several layers. Parameters are fitted per-layer within one period, then applied to all periods. After every move a periodicity keeper rescales the layer thicknesses of each stack with N > 1, in proportion to each layer's thickness and within its bounds, so that the period D keeps its value — or, with Free period checked, stays inside its window.

The period is fixed unless you free it. By default a Periodic fit holds the period D of every repeating stack at its value in the start model: it changes the ratio of the layer thicknesses (and σ, ρ), not D, so it cannot move the Bragg peaks. Set the period first — the peak positions must already match — or check Free period ± in the Fitting panel v3.9.4. D may then move by that percentage of the value it starts from (default 10 %, the bound the fitting procedure uses), each layer still within its own thickness limits; the periodicity keeper steps in only when the sum leaves the window. The window is taken around the model the fit starts from, so Resume Fitting carries on from the period the last fit reached. A stack whose thicknesses are all frozen keeps its period. It is the same engine the MCP server's "target": "period" drives (see MCP Server > Fitting).
  • Suitable for structures with consistent periodicity.
  • Dramatically reduces the number of fitting variables for PMMs.

Polynomial Mode

Arbitrary distributions of structural parameters across the stack can be described by polynomial functions of the period number. Instead of fitting N individual layer thicknesses, the software fits just a few polynomial coefficients (a1–ak) plus the base value x0:

x(j) = x0 + a1(j − 1) + a2(j − 1)² + … + ak(j − 1)k, j = 1, 2, … the period number, x0 the first period's value.

Only repeating stacks (N > 1) and parameters that are not paired get coefficients; the others keep a single value. The period is not held, so the Bragg peaks can move. Keep the order low (≤ 5 in practice): high powers of the period number grow very fast, and the order is limited to 1–9 (a number outside is set to the nearest limit, an entry that is not a number to 1).

  • Order: Maximum polynomial order, 1 to 9 (1 = linear, 2 = quadratic, etc.)
  • Useful for smooth, continuous parameter gradients (e.g. graded-period supermirrors, PMMs with unstable deposition rate).

GPU Acceleration v3.9.0

Each iteration of the fit scores every particle of the swarm, and almost all of that time goes into the Parratt recursion over every layer at every measured angle. When the computer has a graphics card, X-Ray Calc 3 hands the whole swarm to it in one piece: every particle at every angle is computed at once, together with the resolution convolution and the χ². The models themselves are still built on the CPU, in parallel.

  • On a modern graphics card an iteration runs one to two orders of magnitude faster than on all CPU cores (for a 150-period W/B4C multilayer measured at 2000 points, about 70× with 500 particles and 170× with 5000, against all 32 threads of a Ryzen 9 9950X3D on an RTX 5080). That makes much larger swarms practical.
  • Small models gain less: with a few layers and a few hundred points the fixed cost of each iteration dominates.
  • The GPU computes in single precision, like the CPU engine, and its accuracy against a double-precision reference is at least as good. Its χ² agrees with the CPU's well within 1 %, so the search behaves the same; it follows a different path through the swarm, so a GPU fit and a CPU fit with the same seed do not end on identical numbers.
  • The χ² and the curve reported at the end of a fit are always recomputed on the CPU, so they are exactly what Calc gives for the fitted model.
  • Wavelength scans are fitted on the CPU. If the graphics card is missing or fails, the fit continues on the CPU.

The option is Use the GPU for fitting in Settings > Calc & Fit, on by default. Staged Fitting v3.8.2

A complex model rarely fits well in one pass. Staged fitting lets you settle part of it, hold that part still, and concentrate the search on what remains — typically fitting the periodic stack first, then freezing it and working on the top and bottom stacks with a different weighting.

  1. Run a fit as usual and let it converge.
  2. Freeze the part that has settled — right-click the stack in the structure panel, or use the Fix columns in the Fitting Limits dialog.
  3. Change whatever you want for the next pass, the weight type above all.
  4. Choose Calc > Resume Fitting or click the Resume Fitting toolbar button.

Resume Fitting is available once a fit has produced a result, and differs from Auto Fitting in three ways:

  • It re-centres the search. Every free parameter's window slides so the value the last fit reached sits at its centre, keeping the width you set. A parameter that ended hard against a boundary can therefore carry on past it, instead of being stuck at the wall. The same slide moves a ceiling you set on purpose: a density in the upper half of its window gets a maximum above the one you gave, e.g. C at 2.00 with limits 1.5–2.4 resumes with 1.55–2.45, past the 2.4 you set, and no message says so. A density maximum at or below the table's bulk density (as the dialog shows it, to two decimals) is the exception: it is held, and the window slides down under it with its width kept. A ceiling you set anywhere else is not, so check the ρ maxima in the Fitting Limits dialog before you resume.
  • It keeps your fit extensions without asking. A resumed fit continues from the depth profiles they hold — in Irregular mode from each period's value in the Table — so the stale-extension prompt would be meaningless there.
  • It continues the convergence chart rather than clearing it, so both passes are visible on one axis.

The best χ² is not carried across a resume. Changing the weight type changes what is being minimised, so the two passes' numbers are not on the same scale and comparing them would be misleading.

In Polynomial mode a frozen stack keeps its depth profile: the fit is seeded from the gradient the previous pass produced, so freezing holds the grading rather than flattening it.

Freezing everything leaves nothing to fit, and validation says so.

If the limits still carry a warning when you press Run or Resume in the Fitting Limits dialog, a message lists the warnings and asks Proceed anyway? — for example Warning: C: S value at lower limit. Yes starts the fit as it stands; No returns you to the dialog. On a resume this is common: a roughness the previous pass drove to 0 sits on its lower limit, and the re-centred window cannot go below zero, so the warning returns on every pass until you freeze that parameter or answer Yes. Errors are not offered this way; they must be fixed before the fit starts (see Setting Fit Limits).

Convergence Enhancements v3.6

Version 3.6 introduces several improvements to the LFPSO algorithm that significantly improve convergence speed and reliability. Six enhancements are always active and require no configuration; one is optional.

Always-On Improvements

EnhancementDescription
Reflective boundaries When a particle exceeds the search domain, it bounces back into the valid range (like a ball hitting a wall) with 0.5× velocity damping, instead of being clamped at the boundary. This prevents particles from “sticking” at limits and keeps them active in the search. (Irregular and Periodic modes; in Polynomial mode the profile must stay within the limits in every period: higher-order coefficients are zeroed from the top order down until it does, and x0 is clamped last.)
Adaptive Lévy scale The Lévy flight step size starts large (0.10) for broad exploration and decreases to 0.01 by the end of fitting for fine-tuning. Previously, a fixed value of 0.01 was used throughout.
Adaptive PSO/Lévy switching Each iteration the whole swarm takes either a Lévy or a PSO step, chosen by one random draw. The Lévy probability falls from 70% to 30% over the run and rises by 5 points for every non-improving iteration since the last shake (at most 90%). Previously, a fixed 50/50 split was used.
Random-peer Lévy targets 30% of Lévy flights are directed toward a randomly chosen peer particle instead of the global best. This creates diverse search directions and helps explore regions that global-best targeting would miss — particularly valuable for the multimodal fitness landscapes common in X-ray reflectivity.
Population diversity monitoring The algorithm now tracks the normalized spread of particle positions across all parameters, providing a measure of how converged or diverse the swarm is.
Diversity-aware shake The shake mechanism now checks population diversity before triggering. If the swarm is still diverse (spread ≥ 1% of parameter ranges), the shake is delayed for up to 3 additional iterations to let ongoing exploration proceed. If diversity has collapsed (< 1%), the shake fires immediately. This prevents premature reinitializations that waste computation.

Constriction Factor (Optional)

When the Constriction factor checkbox is enabled in Advanced Settings, the standard linear inertia weight decay is replaced by the Clerc-Kennedy constriction coefficient:

V = χ × (V + φ1r1(pbest − X) + φ2r2(gbest − X))
where φ = φ1 + φ2 = 4.1,   χ = 2 / |2 − φ − √(φ² − 4φ)| ≈ 0.7298

pbest is the best particle of the current iteration: the swarm keeps no per-particle memory. In a Lévy iteration the previous velocity is replaced by the Lévy step, aimed at gbest or, 30% of the time, at a random peer.

Unlike the empirical linear schedule, the constriction coefficient is mathematically proven to guarantee convergence while maintaining effective exploration. The higher cognitive and social coefficients (φ1 = φ2 = 2.05 vs. the previous c1 = c2 = 1) give particles stronger attraction to good solutions, while the constriction factor prevents velocity explosion.

When to use: The constriction factor is enabled by default and is recommended for most problems. Consider disabling it if you notice premature convergence on problems with many sharp local minima — the linear inertia decay may provide more aggressive exploration in such cases. When disabled, the ω1 and ω2 parameters in the LFPSO section control the inertia schedule.

Understanding the Cost Function

The cost function, shown as χ², measures the deviation between the calculated and the measured XRR curve. It is the weighted mean of the squared relative residuals of the logarithms, scaled by 1000:

χ² = (1000 / (N − 1)) × Σi [ (log Iexp,i − log Icalc,i) / log Icalc,i ]² × ωpeak,i × ωθ,i

where Iexp,i and Icalc,i are the measured and computed intensities at the i-th measured angle, N is the number of measured points, ωpeak is the peak weight and ωθ the incidence-angle weight. The sum runs over every measured point except half the resolution-convolution window at each end (the points within about 0.1° of it), which the convolution cannot compute in full. Without a resolution every point is summed. (Before 3.9.3.1010 one further point was dropped at the end, whether or not there was a convolution.) The calculated curve is floored at the lower limit of the chart's reflectivity axis (1E-7 by default), so that setting also affects χ² wherever the data fall below it. With Solve scale in χ² checked, log Iexp,i carries the solved offset a.

Peak Weight Function (PW χ²)

Specifically designed for periodic multilayer mirrors. Parameters of the periodic stack primarily affect the intensity of primary diffraction peaks, while Kiessig fringes are affected by the substrate and surface layers. The peak weight concentrates the fit on the primary features of the curve. The measured curve is averaged over a moving window of 5 % of its points (stored in the project, not editable in the program; the first half-window of points always gets weight 1); a point that stands more than three times above that average — a Bragg peak — gets the weight ωpeak = Iexp / average, every other point the weight 1. Unchecked, ωpeak = 1 everywhere.

Incidence-Angle Weight Function (TW χ²)

Allows concentration of the fitting process on distinct segments of the XRR curve by weighting different angular regions differently: ωθ is 1, θ², θ, √θ, 1/θ² or 1/√θ as set in the TW χ² list.

Plain χ²

The Chart Info bar also shows the plain χ²: the same sum with both weights set to 1. It is never minimised; it reports the bare disagreement between data and model on the same scale as the χ², so that fits made with different weight settings can still be compared.

Key properties of the cost function:

  • Lower is better — χ² = 0 means a perfect fit
  • Displayed in the Chart Info bar as both current and best values, beside the scale it was taken at
  • Calculated on the logarithm of the intensity, so that the reflectivity's fall over many decades does not leave the high-angle part of the curve without weight
  • Each residual is relative to log Icalc: the points where the reflectivity is close to 1, near and below the critical angle, weigh the most
  • The value depends on the weights, so χ² values are comparable only between fits made with the same PW, TW and scale settings; the plain χ² removes the weights but not the scale

Solving the Measured Scale

A reflectometer does not measure reflectivity. It counts reflected photons, and the reflectivity is that count divided by the intensity of the incident beam, R(θ) = I(θ) / I0. I0 is seldom known to better than several per cent: it comes from a separate direct-beam scan through attenuators whose factors are themselves calibrated, the source drifts between that scan and the measurement, and the detector loses counts at high rates. What reaches the detector at small angles also depends on the specimen:

  • Footprint. A beam of height b illuminates a length b / sin θ of the specimen. Below the angle at which that length equals the specimen's, part of the beam misses the specimen, and the measured plateau of total external reflection is lower than the true one.
  • Alignment and curvature. An error in the ω zero, or a bowed substrate, lowers and reshapes the region around the critical angle, where the curve is steepest.
  • Normalisation. Normalize sets the scale from a single point — in the automatic variant the largest measured intensity of the curve, matched to the model at that angle. The anchor inherits whatever error that one point carries, and depends on the model it was matched to.

All of these multiply the whole curve by one factor s: Imeas(θ) = s · R(θ). On the logarithmic scale the fit works on, a factor is a constant offset, log Imeas = log R + log s: the measured curve moves up or down without changing shape. That does not move a Bragg peak or change the spacing of the Kiessig fringes, which the thicknesses set, but it changes every absolute intensity — the height of the plateau, the reflectivity of the Bragg peaks, the rate at which the curve falls — and those are what the fit reads roughness and density from. A fit held at a wrong scale reaches for the parameters that can raise or lower the whole curve: a scale that is too low is typically absorbed as extra roughness, one that is too high as extra density contrast. The structure comes out biased, and its χ² is higher than the structure deserves.

What the option does

With Solve scale in χ² checked, the scale is treated as a nuisance parameter: a quantity the χ² needs but which is not itself a result. Every candidate structure the swarm tries is scored at the scale that suits it best. Write a = log10(s / sanchor) for the offset from the anchored scale, and d for a point's residual log Imeas − log Icalc. The offset turns every residual into d + a, and because the χ² is a weighted sum of squared residuals it is a parabola in a:

χ²(a) = S2 + 2a S1 + a² S0,   a* = −S1 / S0

where S0, S1 and S2 are the sums over the points of W, W d and W d², W being the weight the χ² gives a point: the PW and TW weights, and the factor 1/(log Icalc)² that makes every residual a relative one. The best offset a* is minus the weighted mean residual — the shift that centres the residuals on zero. It is found exactly, in the same pass that computes the χ², so the option adds no dimension to the swarm and costs no time. Every candidate is scored at its own a*: the scale is profiled out rather than fitted, and the swarm searches the structure alone.

The weight explains why the scale matters so much. Because each residual is divided by log Icalc, the points near and below the critical angle, where the reflectivity is close to 1 and its logarithm close to 0, weigh the most — and they are also the points that footprint and alignment errors affect most.

The window

A free scale is not harmless. A structure with the wrong density throughout, or a wrong top layer, can look acceptable if the scale is allowed to carry the whole curve to it: the scale would then absorb physics. The Window w says how far you trust the normalisation. The offset is held within ±log10(1 + w), so the solved scale lies between 1/(1 + w) and (1 + w) times the anchored one: the default 0.2 allows a factor of 1.2 either way. A window of 0 pins the scale to the anchor and gives the same χ² as unchecking the option.

  • Widen it when the absolute level is poorly known: no direct-beam measurement, a specimen shorter than the beam footprint at the lowest angles, a curve normalised against a start model far from the answer.
  • Narrow it when I0 was measured carefully and the specimen is larger than the footprint: the window then keeps the scale from covering for a wrong model.

Reading the result

  • The scale pane of the Chart Info bar shows the scale the χ² beside it was taken at. solved ×1.0831 means the measured curve fits best at 1.0831 times its anchored scale, i.e. about 8 % higher; anchored means the option is off. Calc shows it for the model on screen, and at the end of a fit for the fitted model.
  • at bound means the best scale lies outside the window and was held at its edge. Either the normalisation is off by more than the window allows — renormalise, or widen the window if you have a reason to — or the model cannot reproduce the curve's absolute level and the scale was being asked to make up for it. Look at the model before using the numbers of a fit that ends at the bound.
  • A ratio well away from 1 but inside the window says the anchor is poor. Applying the ratio with Data > Normalize and fitting again brings the anchored and the solved numbers together.
  • The chart and the saved data stay at the anchored scale: the measured curve is not redrawn at the solved one, so the model can sit visibly above or below the data by the ratio while the χ² counts it at the solved scale. The plain χ² is taken at the same scale as the χ².
  • A solved χ² is never higher than the anchored χ² of the same structure, since a = 0 is always inside the window, so the two kinds of number cannot be compared with each other. Compare fits made with the same setting; uncheck the option to reproduce the numbers of versions that did not have it.

The option and the window are saved with the project; a project saved before the option existed opens with it checked at 0.2. Export fit results records them as solveScale and scaleSolveWindow under fitParams, together with chi2Scale ("solved" or "anchored"), scaleRatio and scaleClamped. The MCP server's scale_solve and scale_solve_window are the same option with the same defaults: a fit made in the program and one made through the server on the same settings are the same fit.

13Profile Extensions

Function and table profiles that vary a parameter across a periodic structure
On this page
  • Adding a Profile Extension
  • Profile Types
  • Enabling / Disabling Extensions

Profile extensions let layer parameters (H, σ, ρ) vary from period to period of a periodic stack — for example a thickness that drifts during deposition. Both kinds of profile are indexed by the period number n, counting from the surface (n = 1 is the period nearest the surface), not by depth.

Adding a Profile Extension

  1. Select a model in the project tree.
  2. Click the Add Extension toolbar button or choose the extension option from the project toolbar.
  3. The Select type of new extension dialog opens with three choices: Function, Arbitrary values and Roughness function. Function adds a function profile; the other two are disabled in this version (a table profile is created by a fit, see below).

Profile Types

Function Profile

A function profile varies one parameter (H, σ or ρ) of one layer of a periodic stack as a polynomial in the period number n:

v(n) = c0 + c1(n − 1) + c2(n − 1)² + … + cK(n − 1)K,   K ≤ 9

c0 is always the layer’s own value in the structure, so the period nearest the surface keeps the value you entered; you set c1…cK in the Profile Function editor, which previews the resulting profile. A new gradient starts with order 1 and c1 = 0.14. The values are not clamped, so a steep polynomial can drive a thickness, roughness or density negative. Other function forms are not implemented in this version: the function list in the editor is fixed to the polynomial.

A density gradient on a layer with ρ = 0 starts from zero, not from the bulk density (see Layers). The Polynomial fitting mode fits these coefficients.

Table Profile

A table profile holds an individual value of H, σ and ρ for every period of each periodic stack (period 1 = nearest the surface). It is created by an Irregular fit of a periodic structure and shows the fitted values per period as a table and a step chart, which you can copy or save; the values cannot be edited in the table. A model has at most one table profile.

The table is used in calculations only while the Fitting mode is Irregular or Polynomial; in Periodic mode every period uses the stack’s own values.

Enabling / Disabling Extensions

Each extension can be individually enabled or disabled without deleting it. This lets you quickly compare results with and without a particular profile applied.

Tools > Edit Henke Table opens the Henke Table Editor, which allows you to view and modify the atomic scattering factor tables used for reflectivity calculations.

Command-line design of multi-wavelength multilayer mirrors with LFPSO: configuration, output, resume, figure of merit

The Universal Mirror Optimizer is a command-line tool that designs periodic multilayer mirrors (PMMs) optimized for multiple characteristic wavelengths simultaneously. Given a set of target elements (e.g. C Kα and O Kα), the optimizer searches for the best combination of materials, period thickness, layer ratio, number of periods, and interface roughness to maximize reflectivity across all targets at once.

This tool is part of the xrccmd command-line interface and uses the Henke optical constants database of the main X-Ray Calc 3 GUI application. Its reflectivity is a standalone single-precision port of the GUI's Parratt recursion with Névot–Croce roughness (the same σ²/2 exponent as the GUI engine); the substrate is a semi-infinite layer at bulk density.

Concept

Traditional multilayer mirror design targets a single wavelength. When an analytical instrument (e.g. an electron microprobe or X-ray fluorescence spectrometer) needs to measure multiple characteristic lines, the standard approach is to use separate mirrors for each element. The Universal Mirror Optimizer explores whether a single bilayer structure can provide useful reflectivity at two or more wavelengths simultaneously, even if it compromises peak performance at any single wavelength.

The optimizer uses the Virtual Crystal Approximation (VCA) to model mixed-material layers. Each layer’s composition is defined as a weighted mixture of elements from a user-defined pool (e.g. W, Si, C). The atomic scattering factors f1, f2, the atomic mass and the bulk density of the constituents are each averaged with the layer fractions, and the dielectric constant is computed from these mixed values — not by averaging the constituents’ dielectric constants.

Search Space

The optimizer searches over the following parameters:

ParameterDescription

dPeriod thickness in Ångströms
γ (gamma)Fraction of the period taken by layer 1, the upper layer of each period, whatever its material (0–1)

Optimization Algorithm

The optimizer uses its own implementation of Lévy Flight Particle Swarm Optimization (LFPSO), modelled on the GUI fitting engine (see Chapter 9: Convergence Enhancements) but not identical to it: c1 = c2 = 2.05 with the linear inertia w1 + w2(1 − t/T) and no constriction factor, a Lévy scale falling from 0.1 to 0.01, and 30 % of the Lévy flights aimed at a random peer instead of the global best. Key features include:

  • Adaptive PSO/Lévy flight switching: the probability of a Lévy step falls from 0.7 to 0.3 over the run, raised by 0.05 per stagnant iteration (at most +0.2, capped at 0.9)
  • Reflective boundary handling with velocity damping
  • Composition normalization (fractions always sum to 1.0)
  • Window-based shake when the best FoM stalls: if it gains less than 1 % over jamming_max iterations, every particle but one is re-seeded around the global best
  • Parallel fitness evaluation using all available CPU cores

The result reported at the end is the best solution found over the whole run, not the final position of the swarm.

Checkpoint & Resume

Long optimization runs can be interrupted (Ctrl+C) and resumed later. The optimizer handles this gracefully:

  1. Automatic checkpoints — saved every checkpoint_every iterations to checkpoint.json in the output directory.

Figure of Merit

The figure of merit (FoM) combines peak reflectivity and angular bandwidth for all target wavelengths:

FoM = Σi [ weighti × ( wR × Reff,i − wFWHM × FWHMi / FWHMref,i ) ]

where:

  • Reff,i — effective reflectivity for target i, which equals Rpeak,i when w_purity is 0, or purity-adjusted reflectivity when w_purity > 0 (see Spectral Purity)
  • Rpeak,i — peak reflectivity (0–1) for target i, the first-order maximum of the convolved curve in the scan window (see scan_half_range)
  • FWHMi — angular full width at half maximum (degrees) of the Bragg peak
  • FWHMref,i — reference width λi / (Nref·d·cosθB,i), converted to degrees, with θB = asin(λ/2d) and Nref = n_ref (default 50), not the structure's N: a reference tied to N would penalise adding periods, which only raises the reflectivity. It normalizes the FWHM penalty so it is comparable across targets.
  • weighti — per-target weight from the configuration
  • wR, wFWHM — global weights for reflectivity and bandwidth terms

Higher FoM is better. Each target with Rpeak below R_min_threshold, or with θB below theta_min, subtracts 100 from the FoM to steer the swarm toward functional solutions; the reported FoM includes these penalties, so it can be negative. A target without a Bragg condition (λ ≥ 2d) contributes zero and is not penalised.

Spectral Purity

When optimizing a mirror for multiple characteristic wavelengths, higher-order Bragg reflections can cause cross-contamination between measurement channels. For example, a mirror tuned to O Kα (23.6 Å) at its first-order Bragg angle will also reflect wavelengths at λ/2 = 11.8 Å via the second order — which nearly coincides with Na Kα (11.9 Å). When both O and Na are among the target elements, any Na fluorescence reaching the detector at the O measurement angle is misattributed to O.

The spectral purity penalty addresses this by computing a cross-reflectivity matrix and penalizing solutions where contamination is significant.

Cross-Reflectivity Matrix

For each pair of targets i and j, the optimizer computes:

CrossR[j, i] = R(θj, λi)

This is the reflectivity of light with wavelength λi hitting the mirror at the Bragg angle of target j. A high value of CrossR[j, i] means that when the spectrometer measures target j, it also picks up signal from target i’s wavelength via higher-order reflection. The calculation uses the full multilayer reflectivity at each (θ, λ) point — all Bragg orders are naturally included. CrossR is a single-point value at the kinematic Bragg angle of target j, θj = asin(λj/2d), without refraction correction or divergence convolution; it is computed only when w_purity > 0 and only between targets that have a valid Bragg angle, and every line counts equally regardless of its source intensity.

Purity and Effective Reflectivity

For each target j, the purity is defined as:

Purityj = Rpeak,j / ( Rpeak,j + Σi≠j CrossR[j, i] )

Purity ranges from 0 (entirely contaminated) to 1 (no contamination); it is set to 0 when Rpeak,j and the contamination sum are both 0. The effective reflectivity used in the FoM is then:

Reff,j = Rpeak,j × ( 1 + wpurity × ( Purityj − 1 ) )

When w_purity = 0, Reff = Rpeak (no penalty). When w_purity = 1, Reff = Rpeak × Purity, giving maximum penalization of contaminated channels. Intermediate values blend between the two.

Physical Background

Higher-order contamination depends on two structural factors:

  • γ (layer ratio) — controls which orders are suppressed. γ = 0.5 suppresses the even-order reflections (2nd, 4th, …); they vanish exactly only in the kinematic limit with ideal, non-absorbing interfaces, and in the full dynamical calculation they are strongly reduced rather than zero. Values far from 0.5 produce strong even-order peaks. Second-order contamination is typically the most significant.
  • σ (roughness) — interfacial roughness attenuates order m by roughly exp[−(2πmσ/d)²], a Debye–Waller-like factor that is Gaussian in m, so high orders die quickly once σ is a sizeable fraction of d/m. Orders above 4–5 are generally negligible for typical roughness values.
Practical note: The overlap pattern is inherent to the target wavelength set — second-order overlap at λ/2 is independent of the period d. The optimizer can only mitigate overlaps through γ (order suppression), material choice (absorption edges), and roughness. For large element pools with many close-spaced wavelengths, use w_purity = 1.0 and a population ≥ 500 to give the optimizer enough room to find purity-optimized solutions.

  • dual_mirror_results/best_structure_xrc.json — the design to open with the GUI's Import structure…

The reflectivity curve files can be plotted in any graphing tool (Origin, gnuplot, Python/matplotlib) or imported into the X-Ray Calc 3 GUI for comparison with experimental data.

Step 4: Continue optimization (optional)

If you want to refine the result further, increase the iteration count and add a resume path:

{
  ...
  "optimizer": {
    "population": 100,
    "iterations": 1000,
    ...
  },
  "resume_from": "./dual_mirror_results/checkpoint.json"
}

Then re-run: xrccmd -u dual_mirror.json -v

Tips and Best Practices

  • Start small, then refine. Begin with a small population (20–50) and few iterations (50–100) to verify the configuration produces sensible results, then increase for production runs.
  • Element pool size. Each additional element adds composition dimensions for each layer. Pools of 3–5 elements work well. Very large pools may require larger populations.
  • Period range. Ensure dmin > λmax/2 so all targets have valid Bragg conditions. A generous range (e.g. 20–80 Å) allows the optimizer to find the best compromise period.
  • Weighting targets. If one target is more important, increase its weight in the configuration. The optimizer will prioritize that target’s reflectivity at the expense of the others.
  • Interpreting diversity. A random swarm starts near 0.3. A diversity value near zero means all particles have converged to similar solutions. If diversity drops quickly but FoM is still low, consider increasing the population or widening the search ranges.
  • Population JSON. The population.json file contains the 10 best personal bests; they are not deduplicated, so late in a run several may be near-identical. Early or diverse runs often reveal physically different mirror designs (different compositions or periods) with similar overall FoM. Examining them can provide insight into the design trade-space.

Overview

XRC_MCP is a console program that exposes the X-Ray Calc 3 calculation engine to AI assistants over the Model Context Protocol (MCP). An MCP client such as Claude Code starts XRC_MCP.exe, talks to it as JSON-RPC 2.0 over standard input and output, and calls its tools: calculate a reflectivity curve, score a mirror design, run the universal optimizer, fit a measured curve, and read or write .xrcx project files.

The engines are the GUI's own. The curve, the χ² and the figure of merit the server returns are the numbers X-Ray Calc 3 and XRFCalc display for the same structure, and a fit written by the server opens in the GUI as an ordinary project file. This lets you have an assistant prepare, run and compare fits while you verify every result in the GUI.

Property Value

Tools18, grouped below
Long jobsoptimize_mirror and fit_xrr run in the background and are polled
RecordEvery call and result appended to log\calls.jsonl

Installation and Registration

The server needs no configuration file. It takes one mandatory argument, the working directory that becomes its sandbox (see below):

XRC_MCP.exe --workdir "D:\Experiments\RuC-2026-09"

Register it with Claude Code once per experiment directory. The name xrc is how the assistant refers to the server:

claude mcp add -s user xrc -- "C:\Program Files\X-RayCalc3\XRC_MCP.exe" --workdir "D:\Experiments\RuC-2026-09"

Other MCP clients register a stdio server the same way: the command is the path to XRC_MCP.exe, the arguments are --workdir and an absolute path. Nothing in the server depends on the current directory of the process.

To verify the registration, ask the assistant to call describe_server. The reply states the server version, the git revision it was built from, the Henke table directory in use, the unit conventions, and a one-line summary of every tool.

OmniThreadLibrary 3.08: If you build the server yourself, it needs OmniThreadLibrary 3.08 or later. With an older library a job stays at iteration 0 for ever and the server will not exit. See Source Code > Dependencies.

The Working Directory

Every path the server reads or writes lies under the working directory. It is created on first start with four subfolders:

<workdir>\
  projects\        .xrcx files the server writes (save_project) and reads (load_project)
  jobs\            one folder per job: request, progress log, curves, results
  inbox\           measured curves that YOU put there; the server never writes here
    <specimen>\    one folder per specimen, any number of data files inside
  log\
    calls.jsonl    every tools/call and its result, appended, never truncated

A path argument that resolves outside the working directory (a rooted path, a drive letter, a UNC path, or a .. segment) is refused with the error path_outside_workdir; it is never silently remapped.

The journal is the record. log\calls.jsonl holds one line per call with a timestamp, the tool name, the full arguments and the full result or error. Long numeric arrays such as curves are replaced by their length and the SHA-256 of the file they were written to. Keep it with the experiment.

Units and the Structure JSON

The conventions are the program's: thickness, roughness σ and wavelength in ångström, density in g/cm³, angles as the grazing angle θ in degrees (not 2θ). Wherever a wavelength is expected, a photon energy in eV is accepted instead and converted with λ[Å] = 12398.42 / E[eV]; the wavelength actually used is echoed back. (The engine itself looks the Henke tables up with 12398.6; describe_server reports both constants.)

Every tool that takes or returns a layered structure uses one JSON form, listed from the substrate to the surface:

{
  "substrate": {"material": "SiO2", "density": 2.2, "sigma": 3.0},
  "buffer":    {"material": "Ru", "thickness": 197.0, "sigma": 3.0},
  "stacks": [
    {"N": 30, "layers": [
      {"material": "Ru", "thickness": 14.7, "sigma": 3.0, "density": 12.4},
      {"material": "C",  "thickness": 53.8, "sigma": 3.0, "density": 2.2}
    ]}
  ],
  "cap":       {"material": "Ru", "thickness": 20.0, "sigma": 3.0}
}
  • material is a Henke table name, matched case-insensitively (list_materials gives the valid names).
  • density is optional and defaults to the bulk value from the table; the value used is echoed. thickness is required; sigma defaults to 0 and N to 1.
  • buffer (between substrate and first stack) and cap (on top) are optional. Several stacks are allowed.
  • Numbers in the JSON replies are rounded to 6 significant digits; the curve files keep full precision (θ to 7 digits, R as %.8e).

Optimisation and Jobs

Two tools take longer than a request should wait for. They return a job_id at once and run in a background thread; the client waits with job_wait or polls job_status. One job runs at a time, and up to 16 more can queue behind it.

Tool Description
optimize_mirrorSearches for the periodic multilayer that best serves a set of emission lines with the XRFCalc particle swarm. Takes the optimizer configuration (lines, element_pool, excluded pairs, structure ranges, fitness, optimizer settings, substrate, template), a seed and top_k (default 5). The result holds the top_k distinct structures with genome, figure of merit, per-line results and the .xrfx package written for each.
job_statusState of a job without waiting: queued, running, finished, failed, cancelled or unknown, with the current iteration and budget, the best value so far, elapsed seconds and the last message.
job_waitWaits for a job and returns the job_status object plus waited_s. It returns as soon as the job is finished, failed or cancelled, or after wait_s seconds (default 300, at most 900). While it waits the server answers nothing else, so cancel_job cannot reach it; keep wait_s below the client's tool timeout.
job_resultThe result of a finished job. Fails with job_not_finished while it runs, job_failed when it ended in an error, job_cancelled when it was stopped.
cancel_jobAsks a job to stop and returns its state. A running job usually stops within a second or two; poll job_status to see it become cancelled.
Determinism and lifetime: With the same seed and inputs, optimize_mirror and fit_xrr give identical results on the same device; the seed used is echoed. With device: "auto" a machine with a GPU and one without can differ in the last digits, so pin "cpu" or "gpu" for bit-for-bit repeats. Jobs do not survive the server: if the process ends, running jobs are lost and job_status reports unknown after a restart. Each job's folder jobs\<job_id>\ keeps its request, progress log and outputs.

Example Session

A typical exchange, with the assistant's tool calls in order. The curve RuC-07\xrr.dat was copied into the inbox beforehand.

  1. describe_server — confirm the revision and the Henke directory.
  2. list_measurements → finds "RuC-07/xrr.dat"; get_measurement with max_points: 200 to look at the curve.
  3. assess_xrr with the nominal structure — is the curve worth fitting: the plateau against the first order, the orders visible, the points per fringe, the zero counts.
  4. calc_reflectivity with the nominal Ru/C structure (30 periods, d = 68.5 Å) at λ = 1.5406 Å — compare the Bragg peak position with the measurement.
  5. fit_xrr with the period of stack 0 and both layer thicknesses free, smooth: {"passes": 1}, theta_range: {"min": 0.3, "max": 4.0}, seed: 1 → job_id: "fit-20260922-143012-a1b2".
  6. job_wait until finished (tens of seconds on the CPU, much less on a GPU; the result's elapsed_s and iterations_run give the real cost).
  7. job_result → fitted_structure (d is report.period_A; Γ follows from the layer thicknesses), chi2, and the path of fit.xrcx.
  8. save_project with name: "RuC-07-fit" and curves.job_id: "fit-20260922-143012-a1b2" → projects\RuC-07-fit.xrcx, which you open in X-Ray Calc 3 to inspect and refit.
Practice: The lab's rule of thumb for the LFPSO is 100 iterations with 500 to 1000 particles: population wins over iterations. The server's defaults are 500 particles and 100 iterations, the lower end of that rule. They are not the GUI's defaults (the GUI's own population is 1000); the result's optimizer_used lists every value the run used.

Security

  • Sandbox: the server can only read and write under its working directory. A path outside it is refused, never remapped.
  • Read-only inbox: no tool has a write path into inbox\; your measured data cannot be altered by an assistant.
  • No network: the server speaks only over its own stdin and stdout to the client that started it. It opens no ports.
  • Journal: every call and result is appended to log\calls.jsonl; the file is never truncated by the server.
  • Structured errors: failures are returned as {code, message, detail}. The process never shows a dialog or waits for a key, so it is safe to run unattended.

Smoke Test

The repository ships an end-to-end check, XRC_MCP\smoke\session.ps1. It starts the server in a throwaway working directory, calls every one of the 18 tools over one live stdio session (jobs are submitted, polled, waited for with job_wait and read; one is cancelled), and checks the Ru/C Bragg-peak angle, seed determinism of the optimizer and the fit, the path_outside_workdir refusal, that the inbox is byte-identical afterwards, and that the journal holds exactly one line per call.

pwsh -File XRC_MCP\smoke\session.ps1

Exit code 0 means every check passed; -KeepWorkdir leaves the work directories behind for inspection. It takes a few seconds.

Project File (.xrcx)

A ZIP archive of the project's working folder:

  • project.dsc — the project tree (binary): every model's structure (stacks, layers, substrate) as JSON, the titles and descriptions of the data items, and the profile extensions with their coefficients.
  • params.dsc — an INI file with the calculation and fitting settings, no layers: [PARAMS] (N, mode, polarisation, chart minimum), [ANGLE] and [WAVE] (ranges, wavelength, resolution, the 2θ switch), [FIT] and [LFPSO] (fit settings, including SolveScale and ScaleWindow), [INFO] Version, [STATE] (linked data, active model, log scale), and, after a fit (versions after 3.9.4.1130), [FITRESULT]: the last fit's chi-squareds, scale, mode, date, duration, device, seed, program version and data item one per key, and the whole record as Record= JSON, which is what Export fit results writes out.
  • data_<ID>.dat — one text file per data item, in the clipboard layout (three header lines, then angle and reflectivity).
  • calc.dat — the active model's calculated curve.

Data curves are stored with the angle rounded to 0.001° and the reflectivity to five significant digits; Load, Normalize, Smooth and Trim all write through this, so a finer angle step than 0.001° is rounded and can produce repeated angles.

The current project version is 8. A project of version 7 or earlier opens with the substrate density reset to 0 (bulk), because earlier versions ignored the substrate density.

Experimental Data Files

Plain text, one point per line: angle (or wavelength), a single TAB, reflectivity:

* Optional description lines starting with *
0.100	1.000000
0.200	0.999850
...

Column 1: the angle in degrees, 2θ when the calculation's 2θ switch is on and θ when it is off (a text file is not converted), or the wavelength in Å in wavelength mode.
Column 2: reflectivity.

Use exactly one separator (one TAB, or one space in a file without TABs) and no third column; both numbers must start with a digit. Other lines are skipped. The full rules are in Experimental Data > Data Format.

XRDML (PANalytical)

A PANalytical / Malvern .xrdml file, schema 1.0 to 2.x, is read without conversion by Data > Load and by the MCP server's inbox. What is read:

  • the first scan of the file that has data points, its 2Theta positions (start/end, a position list, or Omega for a rocking curve; a file whose 2θ does not move and has no Omega positions is refused);
  • counts (raw, with beamAttenuationFactors multiplied in when present) or intensities (already corrected), divided by commonCountingTime or the per-point countingTimes (left undivided when the file has neither);
  • the wavelength: Kα1 and Kα2 with their ratio, weighted together unless a monochromator or a hybrid mirror is in the incident path;
  • the detector name and read-out period, the sample id, the scan status and start time.

The curve is normalised to 1 at its maximum. A zero or negative count is replaced by the smallest positive rate before it, but never by more than 1000 counts/s (the value used when none precedes it); a text file is floored the same way. The peak count rate of the corrected curve is kept in the description. See Experimental Data > Loading XRDML Files.

Henke Tables

One binary file per material, element or compound, Henke\<Name>.bin (the Henke folder beside the program, or under the storage folder set in Settings). A layer's material name must match a file name. Each file holds:

  • the material name, the molar mass A (g/mol, per formula unit) and the bulk density (g/cm³);
  • records of (photon energy E in eV, f1, f2) on an energy grid. The wavelength is λ = 12398.6 / E (Å); f1 and f2 are interpolated linearly in E.

The optical constants follow from these: δ and β are proportional to (ρ / A) λ² f1 and (ρ / A) λ² f2, with ρ the layer's density, or the bulk density from the file when the layer's is 0. For a compound, f1, f2 and A are all per formula unit, so they must be changed together (see Edit Henke Table). The tables are included with the application.

Settings File (xrc3.ini)

A standard Windows INI file, %APPDATA%\X-RayCalc3\xrc3.ini, or next to the program when a file named uselocaldata sits there. Sections:

  • [Path] — the Henke, storage, benchmark, project, output and jobs folders
  • [Window] — window state, position and size
  • [Options] — CheckForUpdates, UpdateInfoURL, AutoCalc, AutoSave, LiveUpdate
  • [Graphics] — LineWidth
  • [Calc] — NumberOfThreads (0 = all), BenchmarkRuns (20), UseGPU (on). The calculation parameters themselves (range, wavelength, resolution, fit settings) are stored in each project's params.dsc, not here.
  • [Recent] — the recent-projects list

19Illustrative Examples

Single-layer coatings, periodic mirrors, polynomial fitting, and a supermirror
On this page

  • Polynomial Fitting on Graded PMMs
  • Supermirror

The following examples from the literature demonstrate the application of XRC3 to different types of structures (Penkov et al., 2024).

Single-Layer Coating

Evaluation of a single-layer TiZrNi coating deposited by DC magnetron sputtering. The XRR was fitted starting with a two-layer model (TiZrNi + TiO2), which yielded a cost function of ~0.48. Adding extra layers minimized the cost function to 0.14, revealing non-stoichiometric surface layers and hydrocarbon contamination.

Periodic X-Ray Mirrors

Fitting of XRR curves for Mo/Si and Mo/B periodic multilayer mirrors (PMMs) in periodic mode. The Mo/Si results reveal the well-known asymmetric intermixed zones between Mo and Si. For the 2.3 nm period Mo/B PMM, fitting revealed thin asymmetric intermixing zones and a density difference between the thick Mo sublayer (near-bulk density) and the 0.6 nm Mo layers within the periodic structure (84% of bulk).

Polynomial Fitting on Graded PMMs

A W/BN PMM fitted in polynomial mode. The broadening and shape changes of diffraction peaks indicate variation of layer parameters across the stack. Due to unstable deposition conditions, the thickness and roughness of layers were found to vary gradually.

Supermirror

An Sb/B4C supermirror fitted in irregular mode. The project pairs all three parameters of the Sb2B4C layer, only the density of Sb, and the roughness and density of B4C; the other parameters are fitted period by period. The fit gives a depth-graded distribution of the periods, but the individual periods are not uniquely determined: repeat the fit with several runs and compare the distributions before reading detail into any one period.

Application crashes without error message

This is typically caused by running out of memory when solving very large fitting problems (many layers or a very large population size).

Solution: Use the x64 version (XRayCalc3.x64.exe). It calculates and fits as fast as the x32 version and can address much larger amounts of RAM. The x32 version is limited to approximately 2 GB of memory.

An “Unexpected Error” report appears

An error the program does not handle itself opens the X-Ray Calc 3 - Unexpected Error window. The report gives the version, the platform (x32 or x64), Windows and the memory (total, available, load), the error class, its message and where it happened, and the call stack at the moment the error was raised, as offsets into the program's module (since 3.9.4.1090). The same text is written to crash_<date>_<time>.log in the Logs folder of the settings folder (%APPDATA%\X-RayCalc3\Logs\ by default).

What to do: click Copy Report and send the text, with what you were doing and, if you can, the project, to the developer. The call stack is read against the map file of the same build, so give the exact version from the report. Close returns to the program, but save the project under a new name before going on: the operation that failed may have left it half done.

Choosing between x32 and x64

Both versions are included in the distribution:

VersionAdvantageLimitation
x32 (XRayCalc3.exe)The main buildLimited to ~2 GB RAM
x64 (XRayCalc3.x64.exe)Handles large models and populations—

The two calculate and fit at the same speed. Either will do for routine work; switch to x64 when working with large multilayer structures, high population sizes, or when x32 runs out of memory.

Old project folders pile up in the temp folder

X-Ray Calc 3 does not lock projects and never refuses to open one. Every open project is unpacked into a subfolder of %TEMP%\X-RayCalc3\, and the instance that started first (the one that created temp.lock there) clears that folder when it exits. If that instance did not close normally, temp.lock stays behind and the folder is never cleared again. Close every instance of the program and delete temp.lock; the next start takes it over.

Fitting does not converge

  • Widen the fit limits — the initial parameter bounds may be too narrow to contain the true solution.
  • Increase population size — more particles explore the parameter space more thoroughly.
  • Increase iterations — the algorithm may need more time to converge.
  • Enable Shake — this helps escape local minima.
  • Check initial model — a better starting guess leads to faster convergence.
  • Try a different fitting mode — Periodic mode may work better than Irregular for regular multilayers, and vice versa.
  • Check the Bragg peak positions first — a Periodic fit holds the period D of every repeating stack at its start value unless Free period is checked, so by default it cannot move the peaks. Set the period so the peaks line up, check Free period, or fit in Irregular or Polynomial mode (see Fitting Modes).
  • Look at the scale pane — if it reads at bound, the normalisation is off by more than the Window allows: renormalise, or widen the Window (see Solving the Measured Scale).
  • Check the chart's lower reflectivity limit — the calculated curve is floored at it, so measured points below it are compared with that limit.
  • Link the data — the fit needs the measured curve linked to the model and visible; otherwise it stops with Measured curve is not linked!

Calculation is slow

  • Ensure multi-threading is enabled (Settings > Calc & Fit > Auto (Use all)).
  • Reduce the number of calculation points (N) for preliminary calculations. N is used only when no measured curve is linked (or it is hidden); with linked data the model is calculated at the measured angles.
  • For fitting, turn on Settings > Calc & Fit > Use the GPU for fitting (see GPU Acceleration).

Material not found

  • Check the spelling (chemical formula must be exact, e.g., “SiO2” not “Sio2”).
  • The material may not exist in the Henke database. Use Tools > Create new material ... to add it.

Chart appears empty after calculation

  • Check that the angle/wavelength range is appropriate for the structure.
  • For very thin films, use small angles (0.01 to 5 degrees).
  • Switch between linear and logarithmic scale — the reflectivity may be visible only on one scale.
  • Verify that the model has at least one layer defined.

Data import fails

  • Ensure the data file is plain text with two numeric columns.
  • Remove any header lines that are not prefixed with #.
  • Check that decimal separators match your system locale (period vs. comma).
  • Try pasting the data via clipboard instead.

Building

The programs are written in Delphi (Object Pascal) and build with Embarcadero RAD Studio 37.0 (Delphi 13). Win32 is the primary target for the GUI and the CLI; XRC_MCP is built for Win64 only.

In the IDE

  1. Open XRC3.groupproj in RAD Studio.
  2. Choose the Release configuration and the Win32 platform (or Win64 for the 64-bit GUI).
  3. Right-click the project group in the Project Manager and select Build All. The build order is XRayCalc3 → XRayCalcVisualControls → xrccmd → XRFCalc → XRC_MCP.

From the command line

Set the Embarcadero environment variables, then call MSBuild for the project you need. Always use /t:Build; /t:Make does not work with these projects.

set BDS=C:\Program Files (x86)\Embarcadero\Studio\37.0
set BDSCOMMONDIR=C:\Users\Public\Documents\Embarcadero\Studio\37.0
set MSB=C:\Windows\Microsoft.NET\Framework\v4.0.30319\msbuild.exe

%MSB% XRayCalc3\XRayCalc3.dproj /t:Build /p:Config=Release /p:Platform=Win32
%MSB% XRC_CMD\xrccmd.dproj      /t:Build /p:Config=Release /p:Platform=Win32
%MSB% XRFCalc\XRFCalc.dproj     /t:Build /p:Config=Release /p:Platform=Win32
%MSB% XRC_MCP\XRC_MCP.dproj     /t:Build /p:Config=Release /p:Platform=Win64

Executables land in _Out\BIN\. The 64-bit GUI is XRayCalc3.x64.exe; XRayCalc3.exe is the 32-bit build.

Git on PATH: XRC_MCP regenerates XRC_MCP\units\gitrev.inc from git describe --always --dirty in its pre-build event, so git must be on PATH when you build it. The value is what the server reports as its revision; a -dirty suffix means the tree had uncommitted changes when it was built.
