Loading Data from File

  1. Select a model or data item in the project tree.
  2. Choose Data > Load ... or click the Load Data toolbar button.
  3. Pick the file. The dialog opens on XRDML (PANalytical); the other filters are ASCII data (.txt, .csv, .tet), counter files (.dat) and all files. A text file holds two columns (angle or wavelength, and reflectivity); an .xrdml file is read as described below.
  4. The data appears as a series on the main chart, and the file's header lines appear in the data item's description.

Loading XRDML Files

A PANalytical / Malvern .xrdml file (schema 1.0 to 2.x) is read directly, and the file's own facts are used rather than typed in:

  • Angle axis. A 2Theta–Omega scan is in 2θ, a rocking curve in ω. The curve is brought to the unit the 2-theta switch of the calculation settings says, so the chart and the fit see the same angle whichever way the file was scanned.
  • Intensity. Counts are divided by the counting time (beam attenuation factors, when the file has them, are multiplied in) and the curve is normalised to 1 at its maximum. A zero count is replaced by the smallest positive value before it, as a log chart needs. The raw peak count rate, the counting time, the detector and the number of zero counts are written into the item's description, so one count and the detector's range stay recoverable.
  • Wavelength. The wavelength the file implies is written into the calculation settings: for a Kα measurement through an optic that passes both lines it is the doublet weighted by the file's Kα2/Kα1 ratio (1.541874 Å for Cu), for a monochromator or a hybrid mirror it is Kα1. A period fitted at Kα1 when the doublet was measured comes out 0.08 % short.
  • Source file. The path of the file is kept in the description as * Source file:, and Assess XRR quality reads the file again for the count rates the chart no longer carries.
Note: the normalisation to 1 at the maximum is a presentation scale, not a measurement: on a well-aligned specimen the maximum is the total-reflection plateau, on one whose plateau is depressed by alignment it is the first Bragg order. The Normalize step still decides the scale a fit works at.

Pasting Data from Clipboard

  1. Copy two-column data from another application (e.g., a spreadsheet).
  2. Choose Data > Paste from Clipboard or click the Paste Data toolbar button.
  3. The data is imported into the current model.

Data Format

The expected data format is a two-column ASCII text file:

  • 2 columns with TAB as the column separator
  • 3-row header (non-numeric lines are skipped automatically)
  • Column 1: Angle (degrees) or wavelength (Angstroms)
  • Column 2: Reflectivity (typically 0 to 1)

Example:

Sample: Mo/Si multilayer
Date: 2024-01-15
Theta    Reflectivity
0.100   1.000000
0.200   0.999850
0.300   0.998200
0.500   0.956300
1.000   0.523100
2.000   0.012450
5.000   0.000023

Lines starting with # or other non-numeric characters are treated as comments and ignored.

Tip: You can also copy and paste table data directly from OriginLab Origin. The recommended workflow is to import your raw data into Origin first, then copy-paste the two-column table into X-Ray Calc.

Data Processing

Normalize

Data > Normalize opens a dialog where you can manually set the normalization factor. This scales the reflectivity values so the maximum equals 1.0 (or another chosen value).

Data > Normalize (Auto) automatically normalizes the data by dividing all reflectivity values by the maximum value.

Smooth

Data > Smooth applies a Savitzky-Golay smoothing filter to reduce noise in the experimental data while preserving peak shapes.

Trim

Data > Trim removes the low-reflectivity tail of the data (values below a threshold), which can improve fitting convergence by eliminating noisy data points at high angles.

Data Conditioning Walkthrough

Raw experimental data often requires conditioning before fitting. Common issues include a long noisy tail, shadowed regions at low angles, noise, and unnormalized intensity. Here is a typical conditioning workflow:

Step 1 — Normalize. Compare the experimental and calculated intensities at a known point (e.g., the total reflection region). Determine the normalization factor and apply it via Data > Normalize. For example, if the experimental intensity at 0.4° is 0.099, divide by 0.099 to bring the curve to unit reflectivity. The fit need not take this factor as final: with Solve scale in χ² (on by default) it solves the scale within a window around it, since a single point rarely fixes the absolute level to better than several per cent (see Solving the Measured Scale).

Step 2 — Smooth. Apply smoothing to reduce noise: Data > Smooth. This uses a Savitzky-Golay filter that preserves peak shapes while reducing point-to-point scatter.

Step 3 — Trim. Remove data points outside the useful range:

  1. Set the calculation angle range to cover only the reliable portion of the data (e.g., 0.4° to 4.5°).
  2. Click Calc and note the χ² value.
  3. Select Data > Trim to discard points outside the calculation range.
  4. Click Calc again — the χ² should decrease significantly, confirming that noisy tail data has been removed.

After these steps, the experimental curve is ready for fitting.

Assessing a Measurement

Data > Assess XRR quality ... answers one question before any fitting: is this measured curve worth fitting? It runs eight checks on the active data item and shows one row per check with a verdict (pass, warn, fail or unknown), the value, the threshold it was judged against, and a sentence saying why. The same checks are the assess_xrr tool of the MCP server.

CheckWhat it looks at
CountingThe highest count rate the detector saw, against its linear limit. The rate comes from the .xrdml behind the item; a curve loaded from a text file has none.
Plateau vs first orderThe first Bragg order over the low-angle maximum. Above 1 is impossible for a true reflectivity and fails; with a design, a ratio above what the design's own model gives warns. On a single film or a bare substrate the maximum after the plateau is a Kiessig fringe, and the row says so.
Total reflectionWhether the scan starts below the design's critical angle and rises to a plateau. A curve whose maximum is its first point started on the way down and fails.
Orders visibleHow many of the Bragg orders the design puts inside the range stand above the background, against how many the design's model, scaled to the measured plateau, puts there. Fewer measured than expected is a measurement problem, not a fitting one.
Range below backgroundThe fraction of the points at or below the background, and where the useful range ends: the part of the scan that bought nothing. Reported without a verdict.
SamplingPoints per Kiessig fringe, from the design's total thickness, and per order, from its period. Under two points per fringe the fringes are aliased and no fit will see them (fail); under the number in the window (default 3) it warns.
FootprintThe knee asin(beam width / sample length) below which the beam overfills the specimen, and whether the plateau maximum lies below it.
ZerosHow many points have a non-positive count, their fraction, and where they start.

The window holds the numbers nobody records in a file: the detector's linear limit in counts per second, the specimen length and the beam width in millimetres, the resolution the design is convolved with (taken from the calculation settings), the factor above the background an order must stand to count as visible, and the minimum points per fringe. Change any of them and click Assess to re-run. A number left empty leaves its check unknown: the program never invents a threshold. Use the current structure as the design feeds the structure editor's model, including a bare substrate for a glass reference, to the checks that need a period, a thickness or a critical angle.

The text block under the table is one line per check, ready to be filed with the specimen; Copy summary puts it on the clipboard. The overall verdict in the window's title is the worst of the checks.

Tip: the counting and zero-count checks need the raw file. Load the measurement from its .xrdml rather than from a converted text file, and keep the file where it was loaded from: the assessment re-reads it through the * Source file: line of the item's description.

Exporting Data
