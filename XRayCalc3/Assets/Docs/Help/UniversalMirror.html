The Universal Mirror Optimizer is a command-line tool that designs periodic multilayer mirrors (PMMs) optimized for multiple characteristic wavelengths simultaneously. Given a set of target elements (e.g. C Kα and O Kα), the optimizer searches for the best combination of materials, period thickness, layer ratio, number of periods, and interface roughness to maximize reflectivity across all targets at once.

This tool is part of the xrccmd command-line interface and uses the Henke optical constants database of the main X-Ray Calc 3 GUI application. Its reflectivity is a standalone single-precision port of the GUI's Parratt recursion with Névot–Croce roughness (the same 0.50299 σ² coefficient as the GUI engine); the substrate is a semi-infinite layer at bulk density.

Concept

Traditional multilayer mirror design targets a single wavelength. When an analytical instrument (e.g. an electron microprobe or X-ray fluorescence spectrometer) needs to measure multiple characteristic lines, the standard approach is to use separate mirrors for each element. The Universal Mirror Optimizer explores whether a single bilayer structure can provide useful reflectivity at two or more wavelengths simultaneously, even if it compromises peak performance at any single wavelength.

The optimizer uses the Virtual Crystal Approximation (VCA) to model mixed-material layers. Each layer’s composition is defined as a weighted mixture of elements from a user-defined pool (e.g. W, Si, C). The atomic scattering factors f1, f2, the atomic mass and the bulk density of the constituents are each averaged with the layer fractions, and the dielectric constant is computed from these mixed values — not by averaging the constituents’ dielectric constants.

Search Space

The optimizer searches over the following parameters:

ParameterDescription
Composition (per layer)Element fractions for each layer in the bilayer period. Fractions are normalized to sum to 1.0.
dPeriod thickness in Ångströms
γ (gamma)Fraction of the period taken by layer 1, the upper layer of each period, whatever its material (0–1)
NNumber of periods (rounded to integer for evaluation)
σ (sigma)Interface roughness in Ångströms. In bilayer mode it is shared by all interfaces, the substrate's included; in template mode the template's per-layer σ is used and this one applies to the substrate interface only
Density factor (per layer)Multiplier on the bulk density of each layer. It is searched and stored in the checkpoint, but the current fitness code builds every layer at bulk density (factor 1.0), so at present it has no effect on the reflectivity

Optimization Algorithm

The optimizer uses its own implementation of Lévy Flight Particle Swarm Optimization (LFPSO), modelled on the GUI fitting engine (see Chapter 9: Convergence Enhancements) but not identical to it: c1 = c2 = 2.05 with the linear inertia w1 + w2(1 − t/T) and no constriction factor, a Lévy scale falling from 0.1 to 0.01, and 30 % of the Lévy flights aimed at a random peer instead of the global best. Key features include:

  • Adaptive PSO/Lévy flight switching: the probability of a Lévy step falls from 0.7 to 0.3 over the run, raised by 0.05 per stagnant iteration (at most +0.2, capped at 0.9)
  • Reflective boundary handling with velocity damping
  • Composition normalization (fractions always sum to 1.0)
  • Window-based shake when the best FoM stalls: if it gains less than 1 % over jamming_max iterations, every particle but one is re-seeded around the global best
  • Parallel fitness evaluation using all available CPU cores

The result reported at the end is the best solution found over the whole run, not the final position of the swarm.

CLI Usage

The Universal Mirror Optimizer is invoked via the xrccmd command-line tool with the -u switch:

xrccmd -u config.json [-l xrf_lines.json] [-v]
SwitchDescription
-u config.jsonRun the Universal Mirror Optimizer with the specified JSON configuration file
-l xrf_lines.jsonXRF line table (shipped as Shared\Universal\xrf_lines.json). Required when a target is given by name or element range, or as an object without lambda; without it such a run stops with “XRF lines not loaded”.
-vVerbose mode — prints a line at every checkpoint save, and waits for <Enter> before exiting (do not use it in scripts). Shake events are not printed.

The -pop and -iter switches of the other xrccmd modes do not affect -u; the configuration file sets both.

Configuration File

The optimizer is configured via a JSON file with the following sections. Every key shown is required unless it is listed as optional: a missing required key stops the run with an error. The optional keys and their defaults are pure_elements (false), density_factor (1.0), delta_theta (0), theta_min (0), w_purity (1.0), polarization ("sp"), scan_points (200), scan_half_range (0 = adaptive), n_ref (50), excluded_pairs and template_file (none).

Targets

An array of target characteristic lines to optimize for, under the key "lines" or, for older files, "targets" ("lines" wins when both are present). An item is either an object, or a string: an element name such as "O", or an element range such as "B-Mg", whose wavelengths are looked up in the XRF line table (-l) with weight 1.

"targets": [
  {"element": "C",  "lambda": 44.7, "weight": 1.0},
  {"element": "O",  "lambda": 23.6, "weight": 1.0}
]
FieldTypeDescription
elementstringElement name: labels the output, names the curve file and the per_element key, and finds the wavelength in the line table when lambda is omitted
lambdanumberCharacteristic wavelength in Ångströms (e.g. C Kα = 44.7 Å). Optional: taken from the line table (-l) when omitted
weightnumberRelative weight in the figure of merit (optional, default 1). Use higher values to prioritize specific targets.

Element Pool

The set of materials available for layer composition:

"element_pool": ["W", "Si", "C"]

Each element must have a corresponding Henke database file (.bin) in the Henke data directory. The optimizer can mix any combination of these elements in each layer.

Optional "excluded_pairs": ["Mo/Si", …] forbids the listed layer pairs, in either order; it applies in pure-element mode only. Each name must be in the pool.

Structure

Defines the mirror topology and parameter search ranges:

"structure": {
  "type": "bilayer",
  "layers_per_period": 2,
  "pure_elements": true,
  "d":              {"min": 20, "max": 80},
  "gamma":          {"min": 0.2, "max": 0.8},
  "N":              {"min": 20, "max": 100},
  "sigma":          {"min": 0.5, "max": 3},
  "density_factor": {"min": 0.7, "max": 1.3}
}
FieldTypeDescription
typestringRequired but not checked: the structure is always a two-layer period.
layers_per_periodintegerRequired but not checked: the structure is always a two-layer period.
pure_elementsbooleanOptional, default false. When true, each layer is forced to use a single material from the pool (the dominant component). When false, layers can be arbitrary mixtures. Pure-element mode is recommended for most practical applications, and is required for excluded_pairs and templates.
drangePeriod thickness search range in Å. Ensure the range accommodates all target wavelengths (d > λ/2 for a valid Bragg condition).
gammarangeFraction of the period taken by layer 1, the upper layer of each period (0–1). Layer 1 thickness = d×γ, Layer 2 = d×(1−γ).
NrangeNumber of bilayer periods. More periods give sharper peaks but tighter angular tolerance.
sigmarangeInterface roughness in Å: a range object, or a single number to fix the value. Shared by all interfaces in bilayer mode, the substrate's included.
density_factorrangeOptional: a range object, or a single number to fix the value (default 1.0 = bulk density). The value is carried in the search, but the current fitness code ignores it and builds every layer at bulk density; omit it or give a fixed number.
Bragg condition: The period d must satisfy λ/(2d) < 1 for each target wavelength, otherwise no Bragg peak exists. For a target at λ = 44.7 Å, the minimum period is d > 22.35 Å. A target without a Bragg condition contributes zero to the FoM and is not penalised, so check the range yourself.

Fitness

Controls the figure of merit calculation:

"fitness": {
  "w_R": 1.0,
  "w_FWHM": 0.3,
  "R_min_threshold": 0.0001,
  "polarization": "sp",
  "delta_theta": 0.1,
  "theta_min": 3.0,
  "w_purity": 1.0
}
FieldTypeDescription
w_RnumberRequired. Weight for peak reflectivity in the FoM. Higher values emphasize maximizing Rpeak.
w_FWHMnumberRequired. Weight for the FWHM penalty. Higher values penalize broad peaks. Set to 0 to ignore bandwidth.
R_min_thresholdnumberRequired. Minimum acceptable peak reflectivity (after the divergence convolution). Each target below it subtracts 100 from the FoM to drive the swarm away from “dark” solutions.
polarizationstring"s" = s-polarisation; "sp" (the default, and any other value) = unpolarised average (Rs + Rp)/2.
delta_thetanumberInstrumental angular resolution in degrees. The calculated reflectivity curve is convolved with a Gaussian whose FWHM is delta_theta before extracting Rpeak and FWHM. Default 0 = no convolution.
theta_minnumberMinimum acceptable Bragg angle in degrees (default 0 = none). A target whose Bragg angle falls below it subtracts 100 from the FoM and is left out of the FoM sum and of the purity. Prevents solutions at impractically low grazing angles.
w_puritynumberWeight for the spectral purity penalty (0–1). Controls how strongly higher-order Bragg peak contamination between targets is penalized. 0 = no purity penalty, 1 = full penalty. Default: 1.0. See Spectral Purity.
scan_pointsintegerMinimum number of points in the scan around each Bragg peak; the grid is refined to at least 10 points per kinematic peak width, at most 20000. Default: 200.
scan_half_rangenumberFixed half-range of the scan in degrees. Default 0 = adaptive: ±max(0.5°, 4 kinematic widths) around both the kinematic Bragg angle and the refraction-corrected one (sin²θ′ = sin²θB + 2δ, δ averaged over the stack), never starting below 1.15 θc or theta_min + 0.1°, and widened once (up to ±5°) if the peak is clipped. The kinematic width uses the structure's own N.
n_refintegerNumber of periods of the reference width FWHMref in the FoM (see Figure of Merit). Default: 50.

Rpeak is the highest first-order local maximum inside the scan of the convolved curve, and the FWHM is measured between the linearly interpolated half-maximum crossings.

Optimizer

LFPSO algorithm parameters:

"optimizer": {
  "population": 100,
  "iterations": 500,
  "tolerance": 1e-8,
  "stagnation_limit": 50,
  "w1": 0.4,
  "w2": 0.5,
  "jamming_max": 5,
  "checkpoint_every": 50
}
FieldTypeExampleDescription
populationinteger100Number of particles (candidate solutions) in the swarm. Larger populations explore more broadly but run slower per iteration.
iterationsinteger500Maximum number of optimization iterations.
tolerancenumber1e-8Required, but not used by the optimizer.
stagnation_limitinteger50Stop after this many consecutive iterations without improvement of the best solution. A shake resets that counter, so this takes effect only when jamming_max ≥ stagnation_limit; with the example values the run always goes to iterations.
w1number0.4PSO inertia weight (permanent velocity component).
w2number0.5PSO inertia reducing factor (decays over iterations).
jamming_maxinteger5Length of the stagnation window. At the end of each window, if the best FoM improved by less than 1 %, the swarm is shaken: all particles but one are re-seeded within ±10 % of each range around the global best (in pure mode each layer also has a 50 % chance of a random element), and their velocities are reset.
checkpoint_everyinteger50Save a checkpoint file every N iterations. Must be ≥ 1 (0 stops the run with a division-by-zero error after the first iteration). To effectively disable periodic checkpoints, set it larger than iterations; a final checkpoint is always written.
Recommended settings: For a 3-element pool with 2 targets, population: 100 and iterations: 500 is a good starting point. Increase population for larger element pools. Reduce iterations for quick exploratory runs.

Period Templates

With template_file set, in pure-element mode, a period whose layer-1/layer-2 pair matches a template key is built from the template instead of as a plain bilayer. Each template layer gives a material, a thickness ("gamma", "1-gamma" or a fixed value in Å), a sigma and a density; fixed interlayers are subtracted from the nearest main layer, and a period whose interlayers would need a negative main-layer thickness is penalised by 1. Optional caps/cap add a capping layer whose thickness and variant are searched. Template materials are loaded in addition to the pool.

best_structure.json Format

The output structure file contains two sections:

  • optimizer_result — numerical results: FoM, structural parameters (d, γ, N, σ), layer compositions, and per-element R_peak and FWHM.
  • structure — a summary of the stack: the periodic bilayer with layer thickness and roughness (the third value is always 1.0), and the substrate written as [0, 1, 8.0]. For the GUI use best_structure_xrc.json.

Reflectivity Curve Files

Each .dat file in the best_curves/ subdirectory contains the reflectivity for that target wavelength over the same window the figure of merit used (see scan_half_range), without the re-scan of a clipped peak; its length varies, and the convolution trims points at each end. The data is tab-separated:

Checkpoint & Resume

Long optimization runs can be interrupted (Ctrl+C) and resumed later. The optimizer handles this gracefully:

  1. Automatic checkpoints — saved every checkpoint_every iterations to checkpoint.json in the output directory.
  2. Ctrl+C handling — Ctrl+C lets the current iteration finish, then the optimizer writes all the normal result files, the .xrfx package and a final checkpoint.
  3. Resume — set "resume_from" in the configuration file to the path of a checkpoint file. The optimizer restores all particle positions, velocities, personal bests, and the global/all-time best. Every final checkpoint is stamped with the configured iterations, even after Ctrl+C or an early stop, and the run resumes after that stamp: to continue you must raise iterations, otherwise nothing more is run.

Example resume configuration:

{
  "targets": [...],
  "element_pool": ["W", "Si", "C"],
  ...
  "optimizer": {
    "population": 100,
    "iterations": 1000,
    ...
  },
  "output_dir": "./results",
  "resume_from": "./results/checkpoint.json"
}
Important: When resuming, the swarm size comes from the checkpoint (the population value is ignored), and the element_pool must match it. iterations must be larger than the checkpoint's stamp. progress.log restarts.

Figure of Merit

The figure of merit (FoM) combines peak reflectivity and angular bandwidth for all target wavelengths:

FoM = Σi [ weighti × ( wR × Reff,i − wFWHM × FWHMi / FWHMref,i ) ]

where:

  • Reff,i — effective reflectivity for target i, which equals Rpeak,i when w_purity is 0, or purity-adjusted reflectivity when w_purity > 0 (see Spectral Purity)
  • Rpeak,i — peak reflectivity (0–1) for target i, the first-order maximum of the convolved curve in the scan window (see scan_half_range)
  • FWHMi — angular full width at half maximum (degrees) of the Bragg peak
  • FWHMref,i — reference width λi / (Nref·d·cosθB,i), converted to degrees, with θB = asin(λ/2d) and Nref = n_ref (default 50), not the structure's N: a reference tied to N would penalise adding periods, which only raises the reflectivity. It normalizes the FWHM penalty so it is comparable across targets.
  • weighti — per-target weight from the configuration
  • wR, wFWHM — global weights for reflectivity and bandwidth terms

Higher FoM is better. Each target with Rpeak below R_min_threshold, or with θB below theta_min, subtracts 100 from the FoM to steer the swarm toward functional solutions; the reported FoM includes these penalties, so it can be negative. A target without a Bragg condition (λ ≥ 2d) contributes zero and is not penalised.

Spectral Purity

When optimizing a mirror for multiple characteristic wavelengths, higher-order Bragg reflections can cause cross-contamination between measurement channels. For example, a mirror tuned to O Kα (23.6 Å) at its first-order Bragg angle will also reflect wavelengths at λ/2 = 11.8 Å via the second order — which nearly coincides with Na Kα (11.9 Å). When both O and Na are among the target elements, any Na fluorescence reaching the detector at the O measurement angle is misattributed to O.

The spectral purity penalty addresses this by computing a cross-reflectivity matrix and penalizing solutions where contamination is significant.

Cross-Reflectivity Matrix

For each pair of targets i and j, the optimizer computes:

CrossR[j, i] = R(θj, λi)

This is the reflectivity of light with wavelength λi hitting the mirror at the Bragg angle of target j. A high value of CrossR[j, i] means that when the spectrometer measures target j, it also picks up signal from target i’s wavelength via higher-order reflection. The calculation uses the full multilayer reflectivity at each (θ, λ) point — all Bragg orders are naturally included. CrossR is a single-point value at the kinematic Bragg angle of target j, θj = asin(λj/2d), without refraction correction or divergence convolution; it is computed only when w_purity > 0 and only between targets that have a valid Bragg angle, and every line counts equally regardless of its source intensity.

Purity and Effective Reflectivity

For each target j, the purity is defined as:

Purityj = Rpeak,j / ( Rpeak,j + Σi≠j CrossR[j, i] )

Purity ranges from 0 (entirely contaminated) to 1 (no contamination); it is set to 0 when Rpeak,j and the contamination sum are both 0. The effective reflectivity used in the FoM is then:

Reff,j = Rpeak,j × ( 1 + wpurity × ( Purityj − 1 ) )

When w_purity = 0, Reff = Rpeak (no penalty). When w_purity = 1, Reff = Rpeak × Purity, giving maximum penalization of contaminated channels. Intermediate values blend between the two.

Physical Background

Higher-order contamination depends on two structural factors:

  • γ (layer ratio) — controls which orders are suppressed. γ = 0.5 suppresses the even-order reflections (2nd, 4th, …); they vanish exactly only in the kinematic limit with ideal, non-absorbing interfaces, and in the full dynamical calculation they are strongly reduced rather than zero. Values far from 0.5 produce strong even-order peaks. Second-order contamination is typically the most significant.
  • σ (roughness) — interfacial roughness attenuates order m by roughly exp[−(2πmσ/d)²], a Debye–Waller-like factor that is Gaussian in m, so high orders die quickly once σ is a sizeable fraction of d/m. Orders above 4–5 are generally negligible for typical roughness values.
Practical note: The overlap pattern is inherent to the target wavelength set — second-order overlap at λ/2 is independent of the period d. The optimizer can only mitigate overlaps through γ (order suppression), material choice (absorption edges), and roughness. For large element pools with many close-spaced wavelengths, use w_purity = 1.0 and a population ≥ 500 to give the optimizer enough room to find purity-optimized solutions.

Example Workflow

This example designs a multilayer mirror for simultaneous C Kα (44.7 Å) and O Kα (23.6 Å) characterization using W/Si/C materials on a Si substrate.

Step 1: Create the configuration file

Save the following as dual_mirror.json:

{
  "targets": [
    {"element": "C",  "lambda": 44.7, "weight": 1.0},
    {"element": "O",  "lambda": 23.6, "weight": 1.0}
  ],
  "element_pool": ["W", "Si", "C"],
  "structure": {
    "type": "bilayer",
    "layers_per_period": 2,
    "d":              {"min": 20, "max": 80},
    "gamma":          {"min": 0.2, "max": 0.8},
    "N":              {"min": 20, "max": 100},
    "sigma":          {"min": 0.5, "max": 3},
    "density_factor": {"min": 0.7, "max": 1.3}
  },
  "fitness": {
    "w_R": 1.0,
    "w_FWHM": 0.3,
    "R_min_threshold": 0.0001,
    "polarization": "sp"
  },
  "optimizer": {
    "population": 100,
    "iterations": 500,
    "tolerance": 1e-8,
    "stagnation_limit": 50,
    "w1": 0.4,
    "w2": 0.5,
    "jamming_max": 5,
    "checkpoint_every": 50
  },
  "substrate": "Si",
  "henke_path": null,
  "output_dir": "./dual_mirror_results",
  "resume_from": null
}

Step 2: Run the optimizer

xrccmd -u dual_mirror.json -v

The -v flag enables verbose output, showing checkpoint saves, and waits for <Enter> at the end. A typical run with population 100 and 500 iterations takes a few minutes on a modern multi-core CPU.

Step 3: Review results

After completion, examine the output directory:

  • dual_mirror_results/best_structure.json — the optimal mirror design and its performance
  • dual_mirror_results/best_curves/C.dat — reflectivity curve at C Kα (44.7 Å)
  • dual_mirror_results/best_curves/O.dat — reflectivity curve at O Kα (23.6 Å)
  • dual_mirror_results/population.json — top 10 alternative solutions
  • dual_mirror_results/best_structure_xrc.json — the design to open with the GUI's Import structure…

The reflectivity curve files can be plotted in any graphing tool (Origin, gnuplot, Python/matplotlib) or imported into the X-Ray Calc 3 GUI for comparison with experimental data.

Step 4: Continue optimization (optional)

If you want to refine the result further, increase the iteration count and add a resume path:

{
  ...
  "optimizer": {
    "population": 100,
    "iterations": 1000,
    ...
  },
  "resume_from": "./dual_mirror_results/checkpoint.json"
}

Then re-run: xrccmd -u dual_mirror.json -v

Tips and Best Practices

  • Start small, then refine. Begin with a small population (20–50) and few iterations (50–100) to verify the configuration produces sensible results, then increase for production runs.
  • Element pool size. Each additional element adds composition dimensions for each layer. Pools of 3–5 elements work well. Very large pools may require larger populations.
  • Period range. Ensure dmin > λmax/2 so all targets have valid Bragg conditions. A generous range (e.g. 20–80 Å) allows the optimizer to find the best compromise period.
  • Weighting targets. If one target is more important, increase its weight in the configuration. The optimizer will prioritize that target’s reflectivity at the expense of the others.
  • Interpreting diversity. A random swarm starts near 0.3. A diversity value near zero means all particles have converged to similar solutions. If diversity drops quickly but FoM is still low, consider increasing the population or widening the search ranges.
  • Population JSON. The population.json file contains the 10 best personal bests; they are not deduplicated, so late in a run several may be near-identical. Early or diverse runs often reveal physically different mirror designs (different compositions or periods) with similar overall FoM. Examining them can provide insight into the design trade-space.
